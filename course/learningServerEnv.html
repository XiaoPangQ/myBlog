云服务器项目环境配置实战指南

部署不同语言项目前的环境配置全流程：从 SSH 连接、系统初始化，到 Python / Node.js / Java / Go 各语言环境安装，再到 Nginx 反代与进程守护。每一步都附常见问题与解决方法。

11 个章节 覆盖 4 大主流语言 30+ 常见问题 以 Ubuntu 22.04/24.04 为准

01 部署前必读：整体思路

为什么部署总卡在"环境配置"

新买一台云服务器，把代码传上去直接运行——十有八九会失败。因为服务器是一个 裸的 Linux 系统：没有你项目的运行时（Python / Node / JDK）、没有依赖包、没有编译工具，甚至 SSH 都可能连不上（安全组没放行端口）。

环境配置的本质，就是按顺序回答四个问题： 能不能连上 → 系统是否可用 → 语言运行时是否就绪 → 服务能否常驻运行。

整体路线图

 购买服务器（拿到公网 IP）
      │
      ▼
 ① SSH 连接 ────── 安全组放行 22 端口
      │
      ▼

      │
      ▼
 ③ 语言环境 ───── Python │ Node │ Java │ Go（按项目语言选其一）
      │
      ▼
 ④ 拉代码装依赖 ── git clone → pip install / npm install / mvn
      │
      ▼
 ⑤ 进程守护 ───── systemd 服务 / pm2（开机自启 + 崩溃拉起）
      │
      ▼
 ⑥ Nginx 入口 ─── 反向代理 80/443 → 应用端口
      │
      ▼
 ⑦ 验证 ───────── curl 本机 → 浏览器公网 IP 访问

02 连接服务器（SSH）

2.1 第一次连接

买完服务器，在控制台拿到 公网 IP 和 root 密码（或自定义密码）。然后： 

# macOS / Linux / Windows 10+ 自带终端都可以直接用
ssh root@你的公网IP

# 首次连接会提示指纹确认，输入 yes 回车
# Are you sure you want to continue connecting (yes/no)? → yes
# 然后输入密码（输入时屏幕不显示，属正常）
💡 Windows 用户
PowerShell 和 CMD 都自带 ssh 命令。想图形化管理可以用 FinalShell / XShell / MobaXterm，但建议先练熟命令行，排障时只有命令行永远靠得住。

2.2 配置密钥登录（强烈推荐）

密码登录慢且易被暴力破解。在你本地电脑生成密钥对，把公钥传到服务器： 

# ① 本地生成密钥对（已有 ~/.ssh/id_ed25519.pub 可跳过）
ssh-keygen -t ed25519 -C "my-server"

# ② 把公钥传到服务器（macOS / Linux）
ssh-copy-id root@你的公网IP

# ② Windows 没有 ssh-copy-id，用这条等价命令
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@你的公网IP "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

# ③ 之后 ssh root@IP 不再要密码，即成功

2.3 创建日常使用用户（可选但推荐）

长期直接用 root 裸奔有风险，日常建议用普通用户 + sudo：

adduser deploy                        # 按提示设置密码，其他信息一路回车
usermod -aG sudo deploy              # 加入 sudo 组

# 把密钥也复制给新用户，方便直接登录
mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys

ssh deploy@你的公网IP                 # 之后用它登录，需要权限时加 sudo

2.4 连不上服务器？逐条排查

报错现象 最可能原因 解决方法
Connection timed out 云厂商安全组没放行 22 端口 控制台 → 安全组 → 添加入站规则：端口 22、源 0.0.0.0/0、协议 TCP
Connection refused 服务器上 sshd 没在运行，或端口被改过 通过控制台 VNC 登录 → systemctl status ssh → systemctl start ssh
Permission denied 密码错误 / 密钥权限不对 / 用户名错 确认用户名是 root（Ubuntu 镜像有时默认是 ubuntu）；密钥登录时本地私钥权限应为 chmod 600 ~/.ssh/id_ed25519
连接时好时坏 本地网络 / 运营商拦截 换手机热点测试；公司网络找网管放行 22
改了 SSH 端口后连不上 安全组没同步放行新端口 安全组先放行新端口再改 sshd 配置，改完 systemctl restart ssh，并保持旧会话不退出直到确认新端口可用
⚠️ 改 SSH 配置的保命习惯
改 /etc/ssh/sshd_config 前，保持当前窗口不要退出，改完先用新开一个窗口验证能登录，再关闭旧窗口。否则一旦配置写错，你会把自己锁在门外，只能靠控制台 VNC 救援。

03 系统初始化配置

3.1 更新系统

sudo apt update          # 刷新软件源索引（只下载清单，不安装）
sudo apt upgrade -y     # 升级已安装的包

apt 太慢？换国内软件源

# 备份原有源
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# Ubuntu 22.04 换阿里云源（24.04 的源文件在 /etc/apt/sources.list.d/ubuntu.sources，方法相同）
sudo sed -i 's@//.*archive.ubuntu.com@//mirrors.aliyun.com@g' /etc/apt/sources.list

sudo apt update   # 重新生效

3.2 设置时区

sudo timedatectl set-timezone Asia/Shanghai
date                # 验证，应为北京时间

3.3 安装基础工具包

一次性装齐后面所有章节要用的基础工具：

sudo apt install -y \
  git curl wget vim unzip htop \
  build-essential pkg-config libssl-dev

# build-essential = gcc/g++/make，大量 Python/Node 包编译时必需

3.4 安全组 vs 防火墙：新手第一大坑

云服务器的端口访问要过两道闸门，很多人只开了一道： 

 用户浏览器
    │
    ▼ ① 云厂商安全组（网页控制台配置，在服务器之外拦截）
    │      例：只放行 22、80、443
    ▼ ② 系统防火墙（ufw / firewalld，服务器内部拦截）
    │      例：Ubuntu 默认不启用 ufw（全放行）
    ▼
 服务器应用进程（监听 0.0.0.0:端口）
检查项 命令 / 位置 说明
安全组规则 云厂商控制台网页 必须放行你要对外暴露的端口（80/443/22）
ufw 状态（Ubuntu） sudo ufw status 显示 inactive 表示系统层不拦，只需管安全组
firewalld（CentOS） sudo firewall-cmd --list-all CentOS 默认启用且只放行 ssh，要 --add-port
端口是否在监听 ss -tlnp 看应用是否监听 0.0.0.0 而非 127.0.0.1
⚠️ 端口不通排查口诀
外网访问不通时按顺序查三层：安全组放了吗 → 防火墙拦了吗 → 应用监听 0.0.0.0 了吗。90% 的"端口不通"是第一层，9% 是第三层（应用只监听了 127.0.0.1）。

3.5 小内存服务器加 swap（2G 以下必做）

1G/2G 内存的机器在安装依赖（如 npm install、pip 编译）时容易被内核 OOM 杀掉。加一块交换空间当缓冲： 

# 创建 2G swap 文件
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 开机自动挂载
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

free -h       # 看到 Swap 一行有 2.0Gi 即成功

3.6 本章常见问题

现象 原因 解决方法
E: Could not get lock /var/lib/apt/lists 另一个 apt 进程在运行（如自动更新） 等一分钟；或 sudo rm /var/lib/apt/lists/lock 后重试
apt update 报 404 系统版本过老，官方源下架 换阿里云/清华镜像源后重试
磁盘莫名被占满 日志膨胀 / apt 缓存堆积 df -h 看分区 → sudo du -sh /var/log/* 找大头 → sudo apt clean

04 Python 项目环境

4.1 铁律：不要动系统自带的 Python

Ubuntu 的 apt、cloud-init 等系统工具依赖自带 Python。卸载或强制升级它会直接把系统搞崩。正确姿势： 系统 Python 只当底座，项目用虚拟环境隔离。

4.2 方式一：venv 虚拟环境（简单项目推荐）

# 安装 venv 和 pip
sudo apt install -y python3-venv python3-pip python3-dev

# 进入项目目录后创建虚拟环境
cd /opt/myapp
python3 -m venv venv

# 激活（激活后命令行前面出现 (venv)）
source venv/bin/activate

# 在虚拟环境里随便装包，不影响系统
pip install -r requirements.txt

# 退出虚拟环境
deactivate

4.3 方式二：Miniconda（多 Python 版本必备）

项目要求特定 Python 版本（如 3.10，而系统是 3.12）时，用 Miniconda 最省心： 

# 下载安装（国内服务器建议用清华镜像）
wget https://mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
# 一路回车 + yes，完成后重开终端

# 创建指定版本的环境
conda create -n myapp python=3.10 -y
conda activate myapp

# conda 也换清华源加速（可选）
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/
conda config --set show_channel_urls yes

4.4 pip 换国内源（必做）

# 一次性配置，永久生效
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 临时使用
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

4.5 快速验证环境可用

# 以 FastAPI 为例
pip install fastapi uvicorn
uvicorn main:app --host 0.0.0.0 --port 8000

# 另开一个 SSH 窗口测试
curl http://127.0.0.1:8000/docs

# Flask 则是
flask run --host 0.0.0.0 --port 5000
⚠️ --host 0.0.0.0 是关键
本地开发默认监听 127.0.0.1（只有服务器自己能访问），服务器部署时必须加 --host 0.0.0.0，否则外网永远访问不到——这是 Python 部署最高频的错误，没有之一。

4.6 Python 环境常见问题

报错 / 现象 原因 解决方法
externally-managed-environment Ubuntu 23.04+ 启用 PEP 668，禁止直接往系统 Python 装包 这是保护机制不是故障。正确做法：进 venv 或 conda 环境再 pip install。不要用 --break-system-packages 绕过
error: Microsoft Visual C++ 14.0 / gcc failed 编译型依赖（如 psycopg2、cryptography）缺编译器或头文件 sudo apt install build-essential python3-dev libssl-dev 后重装
fatal error: Python.h: No such file 缺 Python 开发头文件 sudo apt install python3-dev
pip 下载超时 默认 PyPI 源在国外 换清华/阿里源（见 4.4）
ModuleNotFoundError: No module named 'xxx' 装到了别的环境 / 没激活虚拟环境 which python 确认当前用的解释器；先 source venv/bin/activate
安装 MySQL 客户端包失败 缺 mysql 头文件 sudo apt install default-libmysqlclient-dev（或改用 PyMySQL 纯 Python 实现）

05 Node.js 项目环境

5.1 为什么不用 apt 装 Node

apt install nodejs 装到的版本又旧又难以升级，多项目还会遇到版本冲突。生产推荐 nvm（Node 版本管理器）：一个用户空间内自由切换 Node 版本，卸载干净。

5.2 安装 nvm + Node

# ① 安装 nvm（官方脚本）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 国内服务器装不动 GitHub 时，用镜像
git clone https://gitee.com/mirrors/nvm.git ~/.nvm
echo 'export NVM_DIR="$HOME/.nvm"' >> ~/.bashrc
echo '[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"' >> ~/.bashrc
source ~/.bashrc

# ② 安装 Node（用国内镜像下载二进制，速度快很多）
export NVM_NODEJS_ORG_MIRROR=https://npmmirror.com/mirrors/node
nvm install 20
nvm use 20
nvm alias default 20     # 设为默认版本

# ③ 验证
node -v    # v20.x.x
npm -v

5.3 npm 换国内源（必做）

# 永久换源
npm config set registry https://registry.npmmirror.com

# 验证
npm config get registry

5.4 安装 pm2 守护进程

Node 程序崩了就没了、SSH 断开也会退出。pm2 解决"常驻运行 + 崩溃自动重启 + 开机自启"三件事： 

npm install -g pm2

# 启动应用
pm2 start app.js --name myapp

# 常用命令
pm2 list              # 查看所有应用状态
pm2 logs myapp        # 查看日志（实时滚动）
pm2 restart myapp     # 重启
pm2 stop myapp        # 停止
pm2 monit            # 资源监控面板

# 设置开机自启（重要！）
pm2 save              # 保存当前进程列表
pm2 startup          # 按提示复制输出的命令执行一次

5.5 验证环境

# 写个最小服务测试
cat > app.js <<'EOF'
const http = require('http');
http.createServer((req, res) => res.end('hello server')).listen(3000, '0.0.0.0');
EOF

pm2 start app.js --name test
curl http://127.0.0.1:3000     # 输出 hello server 即成功
pm2 delete test               # 测完删掉

5.6 Node 环境常见问题

报错 / 现象 原因 解决方法
JavaScript heap out of memory（npm install 时） 内存不足（1G/2G 服务器常见） 加 swap（见 3.5）；或临时扩堆：export NODE_OPTIONS=--max-old-space-size=1536
gyp ERR! stack Error: not found: python3 原生模块（node-sass、sharp 等）需要编译环境 sudo apt install build-essential python3；node-sass 已淘汰，尽量换 Dart Sass
SSH 断开程序就停了 进程挂靠在 SSH 会话上 用 pm2 启动；临时调试可用 nohup node app.js &
重启服务器后 pm2 应用没了 没执行开机自启配置 pm2 save + pm2 startup（见 5.4）
npm ERR! code EACCES 权限错误 全局装包用了 sudo 或目录属主混乱 用 nvm 装的 Node 不需要 sudo；已坏时执行 sudo chown -R $(whoami) ~/.npm
不同项目 Node 版本冲突 多项目共用一个 Node 每个项目目录 nvm use 18；pm2 启动时用 pm2 start app.js --interpreter ~/.nvm/versions/node/v18.20.0/bin/node

06 Java 项目环境

6.1 安装 JDK

Java 环境在服务器上只需要运行时。Spring Boot 项目推荐 JDK 17 / 21（LTS 版本）： 

# 安装 OpenJDK 17（LTS）
sudo apt install -y openjdk-17-jdk

# 或安装 JDK 21（最新 LTS）
sudo apt install -y openjdk-21-jdk

# 验证
java -version
javac -version     # 服务器只跑 jar 的话 javac 可不装（-jre-headless 即可）
📌 部署策略建议
Java 的最佳实践是本地/CI 用 Maven 打好 jar 包，只把 jar 传上服务器运行。服务器上只装 JRE 就够，能避免在服务器上配 Maven、下载依赖等一堆麻烦。

6.2 需要在服务器构建时：安装 Maven + 换源

# 安装 Maven
sudo apt install -y maven
mvn -v

# 换阿里云 Maven 镜像（默认中央仓库在国内很慢）
mkdir -p ~/.m2
cat > ~/.m2/settings.xml <<'EOF'
<settings>
  <mirrors>
    <mirror>
      <id>aliyunmaven</id>
      <mirrorOf>*</mirrorOf>
      <name>aliyun</name>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
EOF

# 构建（跳过测试更快）
mvn clean package -DskipTests

6.3 运行并验证

# 前台运行（先测试）
java -jar target/myapp-0.0.1.jar

# Spring Boot 指定环境
java -jar myapp.jar --spring.profiles.active=prod

# 小内存服务器建议限制堆大小
java -Xms256m -Xmx512m -jar myapp.jar

# 另开窗口验证（默认端口 8080）
curl http://127.0.0.1:8080/actuator/health

6.4 Java 环境常见问题

报错 / 现象 原因 解决方法
java: command not found 没装或环境变量没生效 apt 安装后一般自动配好；手动配 JAVA_HOME 见下
多版本冲突，不知道用的哪个 装了多个 JDK sudo update-alternatives --config java 交互切换
程序里时间和北京时间差 8 小时 JVM 时区默认 UTC 启动参数加 -Duser.timezone=Asia/Shanghai，并确认系统时区已设置（3.2）
启动即被杀 / Cannot allocate memory JVM 默认按物理内存 1/4 要堆，超出限制 显式限制 -Xmx；1G 机器建议 -Xmx512m 起步
Maven 下载依赖极慢/超时 默认走国外中央仓库 配置阿里云镜像（见 6.2）
Unsupported class file major version 编译用的 JDK 比运行时新 服务器升级 JDK，或本地降低编译目标版本

手动配置 JAVA_HOME（需要时）

# 找到安装路径
update-alternatives --list java
# 例如 /usr/lib/jvm/java-17-openjdk-amd64/bin/java

echo 'export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64' >> ~/.bashrc
echo 'export PATH=$JAVA_HOME/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

07 Go 项目环境

7.1 安装 Go（官方 tar.gz 方式）

apt 源里的 Go 版本偏旧，推荐直接装官方二进制包：

# ① 下载（国内用 golang.google.cn 镜像，版本号按需替换）
wget https://golang.google.cn/dl/go1.22.5.linux-amd64.tar.gz

# ② 解压到 /usr/local（官方推荐路径）
sudo rm -rf /usr/local/go        # 清掉旧版本，否则新旧混用会出错
sudo tar -C /usr/local -xzf go1.22.5.linux-amd64.tar.gz

# ③ 配置环境变量
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.profile
source ~/.profile

# ④ 验证
go version    # go version go1.22.5 linux/amd64

7.2 配置国内模块代理（必做）

# 不配代理拉依赖基本必超时
go env -w GOPROXY=https://goproxy.cn,direct

# 验证
go env GOPROXY

7.3 编译并运行

# 在项目目录拉依赖并编译

./server       # 前台测试

# 也可以在本地电脑交叉编译好，只传二进制上服务器（服务器零依赖）
# Mac/Windows 本地执行：

💡 Go 部署的最大优势
Go 编译出的是静态单文件二进制，服务器上可以完全不装 Go 环境——本地交叉编译后 scp 上去直接跑。这也是它被称为"部署最省心的语言"的原因。

09 Nginx 统一入口

9.1 为什么要 Nginx

统一端口

所有应用共享 80/443，按域名/路径分发，不用暴露一堆奇怪端口。

静态资源

前端产物、图片直接由 Nginx 返回，不占应用进程资源。

安全缓冲

应用进程不直接暴露公网，隐藏真实端口与架构。

后续扩展

HTTPS 证书、限流、gzip 都在这里加。

9.2 安装

sudo apt install -y nginx
sudo systemctl enable --now nginx

# 浏览器访问 http://服务器IP 应看到 Nginx 欢迎页

9.3 配置反向代理（后端 API）

# /etc/nginx/sites-available/myapp.conf
server {
    listen 80;
    server_name _;              # 有域名就填域名，如 api.example.com

    location / {
        proxy_pass http://127.0.0.1:8000;      # 转发到你的应用端口
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# 启用站点（软链接 + 检查 + 重载）
sudo ln -s /etc/nginx/sites-available/myapp.conf /etc/nginx/sites-enabled/
sudo nginx -t                 # 语法检查，必须显示 ok
sudo systemctl reload nginx

9.4 配置静态托管（前端 SPA）

server {
    listen 80;
    server_name _;
    root /var/www/myapp;        # dist 上传的位置
    index index.html;

    # Vue/React Router 的 history 模式必须加这段，否则刷新 404
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 前后端同站：/api 开头的请求转发给后端
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
    }
}

9.5 Nginx 常见问题

现象 原因 解决方法
502 Bad Gateway 后端应用没起来 / 崩了 先 curl 127.0.0.1:8000 确认应用活着；看应用日志（pm2 logs / journalctl）
502 且应用确实在跑 应用监听的是 127.0.0.1 之外的错误地址，或用了 IPv6 ss -tlnp 核对实际监听地址与 proxy_pass 完全一致
nginx: [emerg] bind() to 0.0.0.0:80 failed 80 端口被占（另一个 nginx / Apache） sudo ss -tlnp | grep :80 找到占用者； Apache 用 sudo systemctl disable --now apache2
403 Forbidden（静态站点） 目录无执行权限 / 路径错了 sudo chmod -R 755 /var/www/myapp；确认 root 路径下真有 index.html
改了配置没生效 忘了 reload sudo nginx -t && sudo systemctl reload nginx
SPA 刷新页面 404 缺 history 回退规则 加 try_files $uri $uri/ /index.html;

10 进程守护 systemd

10.1 为什么不用 nohup

nohup java -jar app.jar & 能让进程在你断开 SSH 后存活，但服务器重启后不会自动拉起，崩溃了也没人管。systemd 是 Linux 自带的服务管理器，一条配置同时解决：开机自启、崩溃重启、日志收集。

10.2 通用服务模板（以 Java 为例）

# /etc/systemd/system/myapp.service
[Unit]
Description=My Java App
After=network.target

[Service]
User=deploy
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/myapp/myapp.jar
Restart=always                    # 崩溃后 3 秒自动重启
RestartSec=3

[Install]
WantedBy=multi-user.target

10.3 各语言 ExecStart 怎么写

语言 ExecStart 示例
Python (FastAPI) ExecStart=/opt/myapp/venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
Python (Flask + Gunicorn) ExecStart=/opt/myapp/venv/bin/gunicorn -w 4 -b 0.0.0.0:8000 app:app
Node ExecStart=/home/deploy/.nvm/versions/node/v20.15.0/bin/node /opt/myapp/app.js
（Node 项目也可直接用 pm2，不必写 systemd）
Java ExecStart=/usr/bin/java -Xmx512m -jar /opt/myapp/myapp.jar
Go ExecStart=/opt/myapp/server
⚠️ ExecStart 必须写绝对路径
systemd 启动服务时不加载你的 .bashrc/.profile，PATH 很精简。Python 虚拟环境、nvm 里的 node 都要用完整绝对路径（which uvicorn 查出来抄）。

10.4 服务管理命令

sudo systemctl daemon-reload          # 每次改完 .service 文件必须执行
sudo systemctl enable --now myapp      # 设开机自启 + 立即启动
sudo systemctl status myapp            # 看状态（绿 active 才算成）
sudo systemctl restart myapp           # 重启
sudo journalctl -u myapp -f            # 实时看日志（排障神器）
sudo journalctl -u myapp -n 100        # 最近 100 行日志

10.5 systemd 常见问题

现象 原因 解决方法
status 显示 failed（红） ExecStart 路径错 / 配置文件语法错 sudo journalctl -xeu myapp 看具体报错行
手动能跑，服务起不来 相对路径 / 缺环境变量 / 用户权限 全改绝对路径；需要的环境变量写进 service 文件的 Environment= 行；确认 User 有目录权限
改了 service 文件没反应 忘了 reload sudo systemctl daemon-reload 后 restart
重启服务器后服务没起来 没 enable sudo systemctl enable myapp

11 验证清单与排错总表

11.1 部署完成验证清单

  1. 本机自测：curl 127.0.0.1:应用端口 有响应
  2. 进程守护：systemctl status 或 pm2 list 显示 active
  3. 开机自启：systemctl is-enabled myapp 返回 enabled（pm2 为已执行 save + startup）
  4. Nginx 生效：sudo nginx -t 显示 ok 且已 reload
  5. 外网可达：浏览器访问 http://服务器IP 能打开（安全组已放行 80）
  6. 重启演练：sudo reboot 后 1 分钟，网站自动恢复

11.2 环境配置排错总表（背下来）

现象 先查什么 高频解法
SSH 连不上 云控制台安全组 放行 22 端口入站规则
安装依赖卡住 / 超时 是不是默认国外源 apt / pip / npm / Maven / Go 全部换国内源（各章已给命令）
编译失败（gcc / Python.h） 编译工具链 sudo apt install build-essential python3-dev
安装依赖被 Killed 内存 加 swap；Node 加 NODE_OPTIONS；Java 限 -Xmx
本机 curl 通、外网不通 监听地址 应用必须监听 0.0.0.0 而非 127.0.0.1
还是不通 安全组 → 防火墙 → 监听地址 三层排查 ss -tlnp + 云控制台对照检查
Nginx 502 后端应用是否存活 先 curl 127.0.0.1:端口，再看应用日志
断开 SSH 程序退出 没做进程守护 systemd 服务或 pm2，别裸奔 nohup
重启服务器后全挂 没设开机自启 systemctl enable / pm2 startup + save
时间不对 时区 timedatectl set-timezone Asia/Shanghai

11.3 排障三板斧（万能顺序）

  1. 看服务状态：systemctl status xxx / pm2 list —— 活着吗？
  2. 看日志：journalctl -u xxx -n 50 / pm2 logs —— 报了什么错？
  3. 看网络：ss -tlnp —— 端口在监听吗？监听在哪个地址？
💡 一句话总结
环境配置 = 连上 → 初始化 → 装语言运行时（换国内源）→ 依赖（备好编译器和内存）→ 守护进程（绝对路径）→ Nginx（0.0.0.0 + 安全组）。照这条链路走，部署基本一次过；卡住了，就按三板斧定位。
