1. Node.js 是什么 & 为什么选它

Node.js 不是编程语言，而是让 JavaScript 运行在服务端的运行时环境。它基于 Chrome V8 引擎，让前端工程师也能写后端， 同时又天然适合做高并发 I/O 密集型服务（API、网关、爬虫、实时通信等）。

🟢 一句话理解 Node.js

把 Node.js 想象成 「浏览器之外的 JS 运行环境」：你在前端能用的 JS 语法、异步 API 基本都能用，只是宿主从浏览器换成了操作系统。

1.1 Node.js 的四大核心特性

⚡
非阻塞异步 I/O

单线程 + 事件循环，处理并发请求不靠堆线程，内存占用极低。

📦
npm 生态最丰富

全球最大包管理仓库，300 万+ 现成轮子，几乎任何功能都有人写过。

🔁
前后端语言统一

前端 JS 直接写后端，团队复用技能栈，沟通成本最低。

🚀
启动极快

V8 引擎 + JIT 编译，毫秒级启动，适合 Serverless 与微服务冷启动场景。

1.2 Node.js 最适合的场景

场景 为什么适合
RESTful API / BFF 层 非阻塞 I/O 处理高并发请求，资源占用低
实时应用（WebSocket） 事件驱动天然适配长连接
爬虫 / 批量网络请求 异步并发能力强，写代理最顺手
CLI 工具 / 脚本 语法简单、跨平台、生态成熟
网关 / 反向代理 可作为 Nginx 之外的轻量网关层
Serverless 函数 冷启动 < 100ms，比 JVM 系语言快 10 倍
⚠️ Node.js 不适合的场景

Node.js 是单线程，CPU 密集型任务会被卡死。需要跑大量计算（图像处理、AI 推理、视频转码、密码哈希大量计算）时，应交给其他语言/线程（Worker Threads / 子进程）。

4. 环境搭建（nvm + pnpm）

装 Node.js 不要去官网下安装包，用 nvm 管理多版本。后续切换 LTS / 测试版本、项目锁版本都靠它。

4.1 安装 nvm（Node Version Manager）

macOS / Linux 用官方安装脚本：

# 一行命令装好 nvm（来自 nvm-sh/nvm 官方仓库）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

# 重新打开终端，验证
nvm --version  # 应输出 0.40.1 或更新版本

Windows 用 nvm-windows：

  1. 去 github.com/coreybutler/nvm-windows/releases 下载 nvm-setup.exe。
  2. 双击安装（默认路径即可），安装前先卸载已存在的 Node.js。
  3. 装完新开一个 PowerShell，运行 nvm version 验证。

4.2 安装 Node.js LTS

# 查看当前 LTS 版本（2026 年主线：Node 20 LTS / 22 LTS）
nvm ls-remote --lts

# 安装最新 LTS（推荐 Node 20，更稳）
nvm install 20
nvm install 22   # 想用更新的特性也可以

# 设置默认版本
nvm alias default 20

# 验证
node -v   # v20.x.x
npm -v    # 10.x.x
🟢 为什么用 LTS

LTS（Long Term Support）是官方长期维护版本，生产环境永远选 LTS。Current 版本尝鲜用，别上生产，半年就停止支持。

4.3 项目级 Node 版本锁定

在项目根目录创建 .nvmrc 文件，写入版本号：

# .nvmrc
20

团队成员进入项目后，一行命令就能切换到对应版本：

nvm use    # 自动读取 .nvmrc 并切换
nvm install # 如果本机没装，自动装上

npm / yarn / pnpm 三大主流包管理器的核心对比：

# 创建项目目录

# 装一个常用包

5. 模块系统 CommonJS vs ESM

Node.js 有两套模块系统，新老项目混用很常见。2026 年新项目应默认使用 ESM。

5.1 两套模块系统对比

特性 CommonJS（CJS） ES Modules（ESM）
语法 require() / module.exports import / export
加载方式 同步（运行时） 异步（编译时）
文件后缀 .js 默认 .mjs 或 "type": "module"
浏览器兼容 需打包 原生支持
Tree Shaking 弱 强
典型场景 老项目、Node 内置模块 新项目、TypeScript

5.2 CommonJS 用法（老项目主流）

// utils.js —— 导出
function add(a, b) {
  return a + b
}
module.exports = { add }

// main.js —— 导入
const { add } = require('./utils.js')
console.log(add(1, 2))  // 3

5.3 ESM 用法（2026 新项目推荐）

在 package.json 加 "type": "module"：

{
  "name": "my-app",
  "version": "1.0.0",
  "type": "module"
}
// utils.js —— 导出
export function add(a, b) {
  return a + b
}

// main.js —— 导入
import { add } from './utils.js'
console.log(add(1, 2))  // 3

// 默认导出
// utils.js
export default function greet(name) {
  return `Hello, ${name}`
}

// main.js
import greet from './utils.js'
⚠️ CommonJS 与 ESM 混用的三大坑
  1. 不能 require() ESM：CommonJS 文件里 require() 一个 ESM 模块会失败，必须用 import() 动态导入。
  2. __dirname 在 ESM 不存在：要用 import.meta.url 配合 fileURLToPath 模拟。
  3. JSON 导入不同：CJS require('./data.json')，ESM 必须 import data from './data.json' with { type: 'json' }（Node 20+）。

5.4 ESM 中获取 __dirname 兼容写法

import { fileURLToPath } from 'node:url'
import { dirname } from 'node:path'

const __filename = fileURLToPath(import.meta.url)
const __dirname = dirname(__filename)
console.log(__dirname)

5.5 命名导入 vs 默认导入的选择

🟢 命名导入优于默认导入

命名导入（import { add }）在重构时编辑器能自动同步改名，默认导入（import utils from）很容易出错。第三方库除外（默认导出是它们的约定）。

6. 异步编程三板斧

Node.js 的灵魂是异步。JavaScript 异步写法经历了三代：回调 → Promise → async/await。新代码统一用 async/await。

6.1 三种写法对比

// 假设有一个异步读取文件的函数 readFile()
// 老式：回调地狱（不要这么写）
fs.readFile('a.txt', (err, dataA) => {
  if (err) throw err
  fs.readFile('b.txt', (err, dataB) => {
    if (err) throw err
    console.log(dataA + dataB)
  })
})

// Promise 写法
function readFileAsync(path) {
  return new Promise((resolve, reject) => {
    fs.readFile(path, (err, data) => {
      err ? reject(err) : resolve(data)
    })
  })
}

readFileAsync('a.txt')
  .then(dataA => readFileAsync('b.txt').then(dataB => dataA + dataB))
  .then(result => console.log(result))
  .catch(err => console.error(err))

// ✅ async/await 写法（推荐）
async function main() {
  try {
    const dataA = await readFileAsync('a.txt')
    const dataB = await readFileAsync('b.txt')
    console.log(dataA + dataB)
  } catch (err) {
    console.error(err)
  }
}
main()

6.2 并发控制：Promise.all / Promise.allSettled

// 多个请求并发，谁先失败谁短路 → 用 Promise.all
const [users, posts, comments] = await Promise.all([
  fetch('/api/users').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
  fetch('/api/comments').then(r => r.json())
])

// 多个请求并发，但<strong>所有请求都完成（不管成功失败）</strong> → 用 Promise.allSettled
const results = await Promise.allSettled([
  fetch('/api/a'),
  fetch('/api/b'),
  fetch('/api/c')
])
results.forEach(r => {
  if (r.status === 'fulfilled') console.log('成功：', r.value)
  else console.log('失败：', r.reason)
})
场景 推荐 API
全部成功才算成功 Promise.all
任意一个成功即可 Promise.any
全部完成（不管结果） Promise.allSettled
只要第一个完成 Promise.race

6.3 错误处理最佳实践

🔴 Promise 异常吞掉的坑

没被 await / 没被 catch 的 Promise 异常会变成 UnhandledPromiseRejection，Node 18+ 默认会让进程崩溃。规则：

  • 永远 catch：每个 await 都要在 try/catch 里
  • 顶层兜底：在进程入口加 process.on('unhandledRejection') 兜底 
// 入口兜底（main.js 顶部）
process.on('unhandledRejection', (reason, promise) => {
  console.error('未处理的 Promise 拒绝：', reason)
  // 记录日志、告警、退出等
})

process.on('uncaughtException', (err) => {
  console.error('未捕获的异常：', err)
  process.exit(1)  // 严重错误，直接退出让 PM2 重启
})

6.4 顶层 await

Node 14+ 支持顶层 await（在 ESM 模块顶层直接 await），不再需要包 async IIFE： 

// ESM 模块顶层直接 await（Node 14+）
const config = await fetch('/api/config.json').then(r => r.json())
const db = await connectDB(config.dbUrl)

console.log('配置加载完成，可以启动服务')

7. 事件循环 & Buffer/Stream

理解事件循环是 Node.js 进阶的分水岭。面试常考、线上 bug 排查必备。

7.1 事件循环六个阶段

Node.js 事件循环按顺序循环执行这六个阶段，每个阶段都有自己的任务队列： 

   ┌───────────────────────────┐
┌─>│       timers              │ ← setTimeout / setInterval 回调
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │  pending callbacks        │ ← 系统回调（如 TCP 错误）
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │   idle, prepare           │ ← Node 内部使用
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │       poll                │ ← I/O 回调（最重要的阶段）
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │       check               │ ← setImmediate 回调
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
└──┤    close callbacks        │ ← socket.on('close') 等
   └───────────────────────────┘

7.2 微任务 vs 宏任务

🟢 关键认知

每执行完一个宏任务，就清空所有微任务队列再进入下一个阶段。微任务永远优先于宏任务。

类型 例子
微任务（microtask） Promise.then / queueMicrotask / process.nextTick
宏任务（macrotask） setTimeout / setImmediate / I/O / setInterval

7.3 经典面试题：以下代码的输出顺序是？

console.log('1')

setTimeout(() => console.log('2'), 0)

Promise.resolve().then(() => console.log('3'))

process.nextTick(() => console.log('4'))

setImmediate(() => console.log('5'))

console.log('6')

// 答案：1, 6, 4, 3, 2, 5
// 解析：
// 同步：1 → 6
// nextTick 队列：4（nextTick 优先级最高，在微任务之前）
// 微任务队列：3
// timers 阶段：2
// check 阶段：5

7.4 Buffer：处理二进制数据

Buffer 是 Node.js 处理二进制数据的「瑞士军刀」，文件 I/O、网络传输、图片处理都靠它**。 

// 创建 Buffer
const buf1 = Buffer.from('你好')        // 字符串转 Buffer
const buf2 = Buffer.alloc(10)         // 创建 10 字节的零填充 Buffer
const buf3 = Buffer.from([0x68, 0x69]) // 字节数组转 Buffer

// Buffer 转字符串
console.log(buf1.toString('utf8'))    // '你好'
console.log(buf1.toString('hex'))      // 'e4bda0e5a5bd'

// 常用操作
const a = Buffer.from('Hello')
const b = Buffer.from(' World')
const c = Buffer.concat([a, b])        // 拼接 Buffer
console.log(c.toString())              // 'Hello World'

// 文件读取默认返回 Buffer
import { readFile } from 'node:fs/promises'
const data = await readFile('image.png')
console.log(data.length)               // 图片字节数

7.5 Stream：处理大文件的唯一方式

读 1GB 文件用 readFile 会爆；用 Stream 流式读取就不会。所有大文件场景必须用 Stream。 

import { createReadStream, createWriteStream } from 'node:fs'

// 流式复制大文件
const reader = createReadStream('big-input.zip')
const writer = createWriteStream('big-output.zip')

// 管道：自动处理背压（backpressure）
reader.pipe(writer)

// 进阶：HTTP 响应也用 Stream，下载大文件不卡内存
import { createServer } from 'node:http'
import { stat } from 'node:fs/promises'

createServer(async (req, res) => {
  const filePath = './big-video.mp4'
  const stats = await stat(filePath)
  res.setHeader('Content-Length', stats.size)
  createReadStream(filePath).pipe(res)   // 流式响应
}).listen(3000)
🟢 Stream 四种类型速记
  • Readable：可读流（读文件、HTTP 请求）
  • Writable：可写流（写文件、HTTP 响应）
  • Duplex：双工流（TCP socket）
  • Transform：转换流（压缩、加密，zlib.createGzip()）

8. Express 5 实战：RESTful API

Express 是 Node.js 生态使用最广的 Web 框架，2025 年发布了 Express 5 正式版，本指南按 5.x 写。

8.1 初始化项目

mkdir my-api && cd my-api

// src/middlewares/error.ts
import type { ErrorRequestHandler } from 'express'

export const errorHandler: ErrorRequestHandler = (err, req, res, next) => {
  console.error('[ERROR]', err)

  // 自定义业务错误
  if (err.code === 'NOT_FOUND') {
    return res.status(404).json({ error: err.message })
  }
  if (err.code === 'VALIDATION_ERROR') {
    return res.status(400).json({ error: err.message })
  }

  // 默认 500
  res.status(500).json({ error: 'Internal Server Error' })
}

// 自定义错误类
export class AppError extends Error {
  constructor(public code: string, message: string, public status = 400) {
    super(message)
  }
}

// 缓存装饰器模式（读穿透）
export async function cacheAside<T>(
  cacheKey: string,
  ttl: number,         // 秒
  loader: () => Promise<T>
): Promise<T> {
  const cached = await redis.get(cacheKey)
  if (cached) return JSON.parse(cached)
  const fresh = await loader()
  await redis.set(cacheKey, JSON.stringify(fresh), 'EX', ttl)
  return fresh
}

// 用法
async function getUser(id: number) {
  return cacheAside(
    `user:${id}`,        // key
    300,                 // 5 分钟过期
    () => prisma.user.findUnique({ where: { id } })
  )
}

10. 认证安全：JWT + 哈希 + 防护

后端项目上线前必须解决四个问题：身份认证、密码加密、跨域防护、输入校验。本章给出最小安全配置。

10.1 JWT 认证（access + refresh 双 token）

# 装依赖
pnpm add jsonwebtoken bcryptjs zod
pnpm add -D @types/jsonwebtoken @types/bcryptjs
// src/utils/jwt.ts
import jwt from 'jsonwebtoken'

const ACCESS_SECRET = process.env.JWT_ACCESS_SECRET!
const REFRESH_SECRET = process.env.JWT_REFRESH_SECRET!

export interface JwtPayload {
  userId: number
  role: string
}

// access token 短期（2 小时）
export function signAccess(payload: JwtPayload) {
  return jwt.sign(payload, ACCESS_SECRET, { expiresIn: '2h' })
}

// refresh token 长期（7 天）
export function signRefresh(payload: JwtPayload) {
  return jwt.sign(payload, REFRESH_SECRET, { expiresIn: '7d' })
}

export function verifyAccess(token: string): JwtPayload {
  return jwt.verify(token, ACCESS_SECRET) as JwtPayload
}

10.2 bcrypt 密码哈希

// src/utils/hash.ts
import bcrypt from 'bcryptjs'

export async function hashPassword(plain: string): Promise<string> {
  return bcrypt.hash(plain, 12)   // cost = 12 推荐
}

export async function verifyPassword(plain: string, hashed: string): Promise<boolean> {
  return bcrypt.compare(plain, hashed)
}
🟢 密码安全红线
  • ❌ 永远不要明文存密码，必须 bcrypt 哈希
  • ❌ 不要用 MD5 / SHA1，这两个算法已被破解
  • ✅ cost ≥ 10，本指南用 12（100ms 左右）
  • ✅ 数据库只存 hash，不存明文

10.3 登录接口完整实现

// src/controllers/auth.controller.ts
import { userService } from '../services/user.service.js'
import { verifyPassword } from '../utils/hash.ts'
import { signAccess, signRefresh } from '../utils/jwt.ts'
import { AppError } from '../middlewares/error.js'

export const authController = {
  async login(req, res, next) {
    try {
      const { email, password } = req.body
      const user = await userService.findByEmail(email)
      if (!user) throw new AppError('INVALID_CRED', '邮箱或密码错误', 401)

      const ok = await verifyPassword(password, user.password)
      if (!ok) throw new AppError('INVALID_CRED', '邮箱或密码错误', 401)

      const payload = { userId: user.id, role: user.role }
      res.json({
        accessToken: signAccess(payload),
        refreshToken: signRefresh(payload),
        user: { id: user.id, email: user.email, name: user.name }
      })
    } catch (err) {
      next(err)
    }
  },

  async refresh(req, res, next) {
    try {
      const { refreshToken } = req.body
      const payload = verifyAccess(refreshToken)   // 实际用 verifyRefresh
      res.json({ accessToken: signAccess(payload) })
    } catch (err) {
      next(new AppError('INVALID_TOKEN', '无效 token', 401))
    }
  }
}

10.4 鉴权中间件

// src/middlewares/auth.ts
import type { Request, Response, NextFunction } from 'express'
import { verifyAccess } from '../utils/jwt.js'
import { AppError } from './error.js'

export function requireAuth(req: Request, res: Response, next: NextFunction) {
  const auth = req.headers.authorization
  if (!auth?.startsWith('Bearer ')) {
    throw new AppError('NO_TOKEN', '未提供 token', 401)
  }
  try {
    const payload = verifyAccess(auth.slice(7))
    req.user = payload   // 挂到 req 上供后续使用
    next()
  } catch {
    throw new AppError('INVALID_TOKEN', 'token 无效或过期', 401)
  }
}

// 角色权限
export function requireRole(...roles: string[]) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!roles.includes(req.user.role)) {
      throw new AppError('FORBIDDEN', '权限不足', 403)
    }
    next()
  }
}

10.5 输入校验 Zod

// src/middlewares/validate.ts
import type { Request, Response, NextFunction } from 'express'
import { ZodSchema } from 'zod'
import { AppError } from './error.js'

export function validate(schema: ZodSchema) {
  return (req: Request, res: Response, next: NextFunction) => {
    const result = schema.safeParse(req.body)
    if (!result.success) {
      const msg = result.error.issues.map(i => `${i.path.join('.')}: ${i.message}`).join('; ')
      throw new AppError('VALIDATION_ERROR', msg, 400)
    }
    req.body = result.data   // 替换为已校验的数据
    next()
  }
}

// 用法
// src/routes/auth.routes.ts
import { z } from 'zod'

const loginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8).max(64)

11.7 性能优化：Cluster 集群

Node.js 是单进程的，现代服务器都是多核 CPU，必须用 cluster 跑满所有核。 

// cluster.ts —— 手动 cluster
import cluster from 'node:cluster'
import os from 'node:os'

if (cluster.isPrimary) {
  // 主进程：fork 工作进程
  const cpus = os.cpus().length
  console.log(`主进程 ${process.pid} 启动，fork ${cpus} 个工作进程`)
  for (let i = 0; i < cpus; i++) cluster.fork()
  cluster.on('exit', (worker, code, signal) => {
    console.log(`工作进程 ${worker.process.pid} 退出，重启中...`)
    cluster.fork()   // 自动重启
  })
} else {
  // 工作进程：启动 Express
  import('./app.js')
}
🟢 不用 cluster 的两种方案
  1. PM2 集群：运维友好，自动负载均衡（推荐）
  2. Node 内置 cluster 模块：纯代码方案，灵活
  3. Docker 多实例 + Nginx upstream：容器化部署推荐

// 写操作：删除缓存
async function updateUser(id: number, data: any) {
  const user = await prisma.user.update({ where: { id }, data })
  await redis.del(`user:${id}`)
  await redis.del('users:list')   // 列表缓存也要失效
  return user
}
🔴 缓存三大问题

详见 Redis 指南，本节只列出口诀：

  • 穿透：缓存空值、布隆过滤器
  • 击穿：互斥锁重建缓存
  • 雪崩：过期时间加随机值、多级缓存

11.9 监控与健康检查

// 健康检查端点
app.get('/health', async (req, res) => {
  const checks = {
    uptime: process.uptime(),
    timestamp: Date.now(),
    db: 'unknown',
    redis: 'unknown'
  }

  try {
    await prisma.$queryRaw`SELECT 1`
    checks.db = 'ok'
  } catch { checks.db = 'down' }

  try {
    await redis.ping()
    checks.redis = 'ok'
  } catch { checks.redis = 'down' }

  const isHealthy = checks.db === 'ok' && checks.redis === 'ok'
  res.status(isHealthy ? 200 : 503).json(checks)
})

12. 报错速查 & 验证清单

卡住时救命用。把报错对号入座找解决办法。

12.1 安装与环境报错

报错 原因 解决办法
node: command not found Node 没装 / PATH 没配 用 nvm 装，或检查环境变量
npm ERR! ETARGET package.json 版本号写错 用 npm view 包名 versions 查可用版本
pnpm 装包慢 没换源 pnpm config set registry https://registry.npmmirror.com
EBADENGINE Node 版本太低 nvm install 20 升级
ELIFECYCLE npm scripts 报错 看完整 stack trace，通常是 TypeScript 编译错误

12.2 模块与 ESM 报错

报错 原因 解决办法
Cannot use import statement outside a module 没开 ESM package.json 加 "type": "module"，或改后缀为 .mjs
require() of ES Module ... not supported CJS 文件 require 了 ESM 改用 import() 动态加载
__dirname is not defined ESM 没有 __dirname 用 fileURLToPath(import.meta.url) 模拟
Cannot find module 路径错误或没装包 检查 import 路径，pnpm add 装上

12.3 Express 与 HTTP 报错

报错 原因 解决办法
EADDRINUSE 端口被占用 lsof -i :3000 查占用进程，杀掉或换端口
req.body is undefined 没装 express.json() 确认 app.use(express.json())
CORS error 跨域被拦 配置 cors()，或在前端用 proxy
Cannot set headers 已经 res.send 之后又 res.send 检查代码中是否有多个响应
UnhandledPromiseRejection async 函数没 catch 所有 await 都 try/catch，或加全局监听
PayloadTooLargeError 请求体超过 100kb express.json({ limit: '10mb' })

12.4 数据库与 Prisma 报错

报错 原因 解决办法
Can't reach database server DATABASE_URL 错或库没起 检查连接串、确认 MySQL 启动、关防火墙
PrismaClientInitializationError Prisma Client 没生成 pnpm prisma generate
Unique constraint failed 唯一索引冲突 业务层先查询再判断，捕获 P2002 错误码
Foreign key constraint 外键关联数据不存在 确认关联记录已存在再写入
Too many connections 连接池耗尽 单例 Prisma Client，开发期热重载用 globalThis

12.5 JWT 与认证报错

报错 原因 解决办法
JsonWebTokenError: invalid signature 密钥不一致 access / refresh 用不同密钥，前后端一致
TokenExpiredError token 过期 前端拦截 401 后用 refresh token 续签
ENOENT: no such file 读 .env 文件路径不对 确认 .env 在项目根目录，启动用正确 cwd
密码登录一直失败 bcrypt cost 太大 / 数据库存的不是 hash cost 调到 10-12，确认数据库存的是 hash 而非明文

12.6 部署与运维报错

报错 原因 解决办法
PM2 启动后立刻退出 缺环境变量或数据库连不上 pm2 logs 看错误；用 pm2 start 时配 env
容器跑起来后立刻 exit CMD 写错或环境变量缺失 Dockerfile CMD 用绝对路径，docker logs 看输出
Nginx 502 Bad Gateway Node 进程没起或端口不通 确认 Node 在监听、curl 测端口、看 nginx error.log

12.8 Node.js 后端学习口诀

📌 十六句口诀
  1. nvm 装 LTS：永远装 LTS，别用 Current 版本上生产
  2. pnpm 装包：磁盘省、速度快、依赖严格
  3. 新项目用 ESM：package.json 加 type:module，命名导入
  4. 异步用 await：所有 Promise 都 try/catch
  5. 事件循环懂顺序：同步 → nextTick → 微任务 → 宏任务
  6. 大文件用 Stream：readFile 爆内存，pipe 流式处理
  7. 分层架构：route → controller → service → model，职责清晰
  8. Prisma 用 type：generate 后所有查询都有类型提示
  9. 密码 bcrypt：cost ≥ 12，永远不存明文
  10. JWT 双 token：access 短期 + refresh 长期
  11. 输入校验 Zod：请求体 schema 校验后再处理
  12. 日志用 pino：结构化 JSON，不记敏感信息
  13. PM2 集群：跑满所有 CPU 核，自动重启
  14. Nginx 反代 + HTTPS：certbot 免费证书，强制 443
  15. 缓存放 Redis：session、计数器、热点数据
  16. 监控 + 健康检查：/health 端点必做，故障告警自动

按这十六句口诀对照检查，Node.js 后端开发就能上手做项目。指南到这里就结束了，祝你编码愉快。
