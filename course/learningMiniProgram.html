微信小程序部署实战指南

从注册账号到正式上线：ICP 备案、开发者工具、服务器域名或云开发、隐私保护指引、 提交审核、发布与回滚，完整链路逐步操作。每一步卡点都给出对应报错与解决办法， 跟着做就能把小程序真正部署上线。

01 部署全景与账号主体选择

「部署小程序」到底要做什么

和普通网站不同，小程序没有「域名 + 服务器」就完事这么简单。它的上线要过 两道闸门：

  • 平台审核闸门：你的代码要上传到微信服务器，经 微信人工审核通过后发布，用户才能搜到、用到。审核不通过，代码写得再好也上不了线。
  • 合规闸门：小程序涉及网络请求的域名必须 ICP 备案 + HTTPS；涉及用户信息的必须配置 用户隐私保护指引；2023 年 9 月起新小程序还必须先完成 小程序备案才能上架。

所以「部署」实际包含两条线：代码上线线（开发工具 → 上传 → 审核 → 发布）和 后端服务线（自建服务器 + 合法域名，或微信云开发）。 本指南两条线都讲，跟着走即可。

📌 全流程路线图（强烈建议先看这张图）
注册账号（1 天） → 完善信息 + 发起 ICP 备案（与开发并行，1~3 周） → 下载开发者工具 → 创建/导入项目 → 本地模拟器调试 → 真机预览 → 后端就绪（自建域名 / 云开发，可提前做） → 上传代码 → 体验版真机回归 → 提交审核（1~7 天） → 审核通过 → 发布上线 → 日常运维迭代。 备案耗时最长，一定第一时间提交，不要等代码写完才备案。

第一步：选主体类型（个人还是企业）

注册时选的「主体类型」决定了小程序能做多少事，注册后个人主体不能直接升级为企业主体 （只能重新注册或用企业资料做账号迁移），所以先想清楚：

对比项 个人主体 企业 / 个体工商户主体
注册成本 免费，仅需身份证 + 手机号 免费注册；微信认证 300 元/年（个体工商户可用对公或法人扫脸认证）
名称规则 不能含「公司、商城、金融、政务」等词，命名限制多 可用企业名，限制较少
可开类目 仅限个人开放类目（工具、生活服务等基础类目） 全类目（电商、餐饮、医疗、金融等需额外资质）
微信支付 不能开通 可开通（需营业执照 + 商户号）
客服 / 附近的小程序等能力 部分受限 基本全开
适合场景 个人作品、工具类、信息展示、学习 demo 电商、门店、内容平台、任何想商业化的小程序
⚠️ 想清楚再注册
个人主体做不了：微信支付、电商交易、AI 对话类（深度合成需企业认证）等。 如果你未来确定要商业化，直接注册企业主体，别先注册个人号再后悔—— 迁移主体比重新注册麻烦得多。

一个决策帮你选后端方案

后端怎么搭，取决于你有没有服务器、域名和备案条件。先给结论，第 5~7 章展开：

你的情况 推荐方案 原因
没有服务器，个人开发者，想快速上线 微信云开发 免备案域名、免运维，有免费额度，个人主体可用
已有服务器 + 备案域名 自建后端 已有资源直接用，语言框架自由（Nginx 反代）
已有 Docker 镜像 / 想跑完整服务 微信云托管 按容器部署，自动扩缩容，可复用 Docker 技能

本章常见问题

现象 原因 解决方法
个人主体能不能换成企业主体？ 主体类型注册后不可直接修改 用企业资料重新注册，或走「账号迁移」流程（需双方配合），个人资料不支持迁移
注册时主体类型选错了怎么办？ 个人 / 企业信息不可改 若尚未发布内容，尽快用正确主体重新注册一个号
小程序没备案能先开发吗？ 备案与开发互不阻塞 能。备案期间正常开发、真机预览、体验版测试，只是不能提交审核发布
一定要先有代码才能备案吗？ 不需要 备案只需账号信息与服务内容描述，可注册后立刻提交，代码写完备案也基本下来了

02 注册账号与获取 AppID

注册流程（约 10 分钟）

  1. 打开注册页：浏览器访问微信公众平台 mp.weixin.qq.com，点右上角「立即注册」，账号类型选 小程序。
  2. 填邮箱：使用一个从未注册过公众号 / 小程序 / 开放平台 的邮箱，设置密码后去邮箱点激活链接。激活链接 24 小时内有效。
  3. 选主体类型：个人选「个人」，企业/个体户选对应类型。 个人主体需要：管理员本人身份证信息 + 手机号，并用绑定了银行卡的微信扫码验证。
  4. 完善基本信息：设置小程序名称、头像、简介， 选择服务类目。名称 1 年可改 2 次（个人主体改名次数少，想好再填）。
  5. 拿到 AppID：登录后台 → 左侧「开发」→「开发管理」→「开发设置」， 页面顶部就是 AppID（AppSecret 也在这一页，但那是后端调接口用的，务必保密）。
💡 AppID 是什么
AppID 是小程序的唯一身份证（形如 wx1234567890abcdef）。创建项目、真机预览、上传代码、调用微信接口全靠它。 注册完第一件事：把它复制保存好。

类目怎么选：直接决定审核难度

「服务类目」是后台让你选的小程序行业分类。类目选错，审核会被驳回；个人主体可选类目有限。 给你三个实用原则：

  • 个人主体选「工具」类最稳妥，基本不踩红线。
  • 类目要和实际功能一致：简介说查快递，实际是游戏，必然驳回。
  • 涉及医疗、金融、教育、社交等特殊行业，需要前置资质（许可证），没有就别碰。
⚠️ 名称三条红线
① 不得含「国家级、最高级」等广告违禁词；② 不得与已有小程序 / 公众号重名或混淆； ③ 个人主体名称不要出现「公司、商城、金融」等字眼。想好名字先去后台搜一下是否被占用。

本章常见问题

现象 原因 解决方法
提示「邮箱已被注册」 该邮箱注册过公众号 / 小程序 / 开放平台任一账号 换一个全新邮箱；或用该邮箱登录原账号找回密码
激活邮件没收到 / 链接过期 被垃圾箱拦截，或超过 24 小时 查垃圾邮件；过期就在注册页用同邮箱重新获取激活链接
扫码后提示「该微信号已绑定其他账号」 一个微信号只能当一个小程序管理员 用家人/同事的微信做管理员，或解绑原账号后重试
找不到 AppID 入口路径不熟 后台「开发」→「开发管理」→「开发设置」，页面顶部即可见
AppSecret 忘了 / 泄露了 Secret 只在生成时完整显示一次 在开发设置页点「重置」，旧 Secret 立即失效；泄露务必马上重置并加 IP 白名单
想改服务类目改不了 部分类目一经选择不可变更（如游戏） 普通类目可在「设置」→「基本设置」→「服务类目」修改；游戏类目不可改

03 安装开发者工具与创建项目

安装微信开发者工具

  1. 下载地址：developers.weixin.qq.com/miniprogram/dev/devtools/download.html ，选稳定版 Stable（别选 RC 预发布版，图稳定）。
  2. 按操作系统下载安装包，Windows 一路 Next 即可。安装后首次打开， 用管理员微信扫码登录（需要是注册时的管理员或已绑定的开发者）。
💡 工具界面四块区域
顶部工具栏（编译 / 预览 / 上传 / 清缓存）｜ 左侧模拟器（手机预览效果）｜ 中间编辑器（写代码）｜ 底部调试器（Console / Network / Storage，排查问题全靠它）。

创建项目：三种 AppID 怎么选

新建项目时有三种选择，新手常在这里困惑：

选项 说明 什么时候用
测试号（无 AppID） 不需要注册账号，临时体验 只想快速看 demo、学语法
自己的 AppID 正式开发，能预览、上传、调接口 真实项目，部署上线必须用它
游客模式 不登录也能体验工具 极少用，功能受限

选「小程序」模板 + 自己的 AppID，语言选 JavaScript（原生）即可。 若用 uni-app / Taro，用对应 CLI 创建项目后，在本工具里「导入项目」。

项目目录结构（原生小程序）

# 一个最小可运行项目长这样
miniprogram-app/
├── app.js                # 全局逻辑：App() 注册、云开发初始化常写这里
├── app.json              # 全局配置：pages 列表 / window 样式 / tabBar
├── app.wxss              # 全局样式
├── project.config.json   # 项目配置：appid / 编译设置（重要！）
├── sitemap.json          # 索引配置，一般不用动
└── pages/
    ├── index/
    │   ├── index.js       # 页面逻辑（Page()，数据与事件）
    │   ├── index.wxml     # 页面结构（类似 HTML）
    │   ├── index.wxss     # 页面样式
    │   └── index.json     # 页面配置（页面标题等）
    └── logs/
        └── ...
⚠️ app.json 里「pages 数组第一项 = 首页」
新增页面必须同步登记到 app.json 的 pages 数组里， 否则编译报「page not found」。新建页面推荐直接在编辑器里右键 「新建 Page」，会自动注册，别手写。

导入已有项目 / 别人给的项目

选「导入项目」，目录指向含 project.config.json 的文件夹。导入后第一时间检查： 右下角或详情面板里的 AppID 是否是你自己的。别人项目里写死的旧 AppID 会导致预览、上传全部报错。

本章常见问题

现象 原因 解决方法
工具启动白屏 / 打不开 显卡兼容问题或安装损坏 「设置」→「通用设置」→ 关闭「GPU 加速」（或勾选启用）后重启；还不行就重装稳定版
扫码登录后没有项目列表 该微信不是此小程序的开发者 / 管理员 用管理员微信登录；或在小程序后台「管理」→「成员管理」把你加为项目成员（体验者/开发者）
提示 AppID 无效 / 不匹配 project.config.json 里的 appid 与登录账号不一致 详情面板重新填自己的 AppID，或改 project.config.json 的 appid 字段后重新编译
编译报「app.json: not found」 导入时目录选错了层级 目录必须指向含 app.json 的那一层（很多框架是 miniprogram 子目录，选它而不是仓库根目录）
页面报「xxx is not defined」 js 里用了未注册的函数 / 变量 检查 Page() 里 methods 拼写；改动 app.json 后工具会重启编译，稍等即可
改代码后界面没变化 编译缓存 点工具栏「编译」按钮，或「清缓存」→「清除全部缓存」后重新编译

04 本地开发与真机联调

先在模拟器跑通

写完代码点「编译」，模拟器会渲染出手机效果。模拟器≠真机，但它能快速暴露 JS 报错、样式错位。养成习惯：Console 有红点先看 Console，大部分问题 都在这里给了明确提示。

真机预览（手机上跑起来）

  1. 工具栏点「预览」，会生成一个二维码。
  2. 用管理员或已绑定开发者的微信扫码，手机上即可打开小程序（开发版）。
  3. 二维码约 2 分钟失效，过期后点工具里的「刷新」重新生成即可，不用重编译。
  4. 手机上看的是开发版，右上角「···」→「开发调试」可打开调试开关—— 打开后真机上的请求不校验合法域名（联调利器，正式回归要关掉）。

本地后端怎么联调（最容易卡的一步）

你的后端跑在电脑 localhost:8000，小程序直接请求它必然失败，因为：

  • 开发工具里：默认校验域名，localhost 不在白名单 → 在「详情」→「本地设置」勾选 「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。
  • 真机上：手机里的「localhost」是手机自己，不是你的电脑 → 把代码里的地址改成电脑的局域网 IP（如 http://192.168.1.8:8000），手机和电脑连同一个 Wi-Fi， 并确保后端监听 0.0.0.0 而不是只监听 127.0.0.1。
  • 基础库 2.4.0 起允许请求局域网 IP，但不能请求本机 IP； 手机开启「开发调试」后同样跳过域名校验。 
// 联调期建议把 baseURL 收敛到一个文件，上线前只改一处
// config.js
const isDev = false  // 上线前改成 false

module.exports = {
  baseURL: isDev ? 'http://192.168.1.8:8000' : 'https://api.yourdomain.com'
}
🚫 开发版能通 ≠ 上线能通
勾选「不校验域名」只是开发期临时手段。正式版（审核版 + 线上版） 永远强制校验：域名必须 HTTPS + ICP 备案 + 在后台白名单里。 很多人开发版调通了，一上线全挂，就是没搞懂这条。第 5~6 章专门解决它。

真机调试（看手机上的 Console）

预览只能看效果，看不到手机端的报错。需要排查真机问题时，用工具栏 「真机调试」：手机扫码后，工具会实时显示手机上的 Console / Network， 适合定位「模拟器正常、真机异常」的疑难杂症（如机型适配、弱网、权限弹窗）。

本章常见问题

现象 原因 解决方法
预览二维码扫了没反应 二维码过期 / 微信非项目成员 点「刷新」重新生成；确认扫码微信是管理员或已添加的体验成员
真机上请求报 fail（开发版） 域名校验或地址写错 手机端打开「开发调试」再试；确认用局域网 IP 且手机电脑同 Wi-Fi、后端监听 0.0.0.0
请求报 url not in domain list 域名没配白名单 / 没跳过校验 开发期勾选「不校验合法域名」；正式环境去后台配置合法域名（见第 6 章）
模拟器正常、真机白屏或按钮无效 用了真机不兼容 API / 权限弹窗被拒 「真机调试」看真机 Console 报错；重点查 getUserProfile、getLocation 等授权流程
手机打开是旧页面 缓存了旧版本 微信里删除该小程序（长按删除），重新扫码预览

05 后端三方案与域名硬规则

三种后端方案怎么选

对比项 自建服务器 + HTTPS 微信云开发 微信云托管
本质 自己的云服务器跑后端，Nginx 反代 微信提供的云函数 + 云数据库 + 云存储 容器化部署（Docker 镜像直接跑）
是否需要备案域名 需要（服务器在国内必须备案，域名加白名单） 不需要，用 wx.cloud 私有协议调用 不需要额外配置合法域名
技术栈 任意（Node/Python/Java/Go…） Node.js 云函数为主，前端 wx.cloud 直连 任意语言，打包成镜像
成本 服务器 + 域名 + 证书（有免费证书） 有免费额度，超量后按量付费 按容器运行时长 + 流量计费
运维负担 高（自己管服务、证书、监控） 低（平台托管） 中（管镜像，平台管扩缩容）
适用 已有服务器 / 复杂业务 / 要接自己数据库 个人开发者、轻业务、快速上线 想用 Docker、有现成镜像

域名硬规则（背下来，能省 90% 的线上问题）

🚫 六条铁律，违反一条线上请求就失败
① 必须 HTTPS（socket 用 wss），证书须被系统信任、证书链完整、TLS 1.2 以上； ② 域名必须 ICP 备案（服务器在境外也无法豁免——小程序侧强制校验）； ③ 不能用 IP 地址（局域网 IP 联调除外）、不能用 localhost； ④ 后台配置的域名不能带端口，配置后请求 URL 也不能带任何端口（443 也不行）； ⑤ 不支持泛域名 / 父域名，用哪个子域配哪个； ⑥ 每类域名最多 200 个，业务域名（web-view）要单独配置并上传校验文件。

配置位置统一在小程序后台：「开发」→「开发管理」→「开发设置」→「服务器域名」， 四类各配各的：request（wx.request 接口）、uploadFile（wx.uploadFile 上传）、 downloadFile（下载）、socket（wss 长连接）。

💡 记忆口诀
「请求要备案，HTTPS 不能断；IP 端口泛域名，一个都不沾； 后台白名单，子域单独添。」—— 第 6 章带你一条条落实。

06 自建后端：从域名到小程序可调用

本章目标：让小程序 wx.request 能稳定请求到你服务器上的接口。 假设你已有一台云服务器（Ubuntu）且后端已在 localhost:8000 跑通 （本地怎么把项目部署到服务器，参考本系列 云服务器环境配置实战）。

第 1 步：域名解析到服务器

在域名服务商控制台加一条 A 记录：主机记录 api → 记录值填服务器公网 IP。 等 10 分钟左右，用下面命令验证解析是否生效（xxx 是你的域名）： 

# 能看到你服务器的公网 IP，说明解析已生效
$ ping api.yourdomain.com
# 更精确：直接查 DNS
$ nslookup api.yourdomain.com
⚠️ 域名备案别忘
域名指向的服务器在中国大陆，就必须先完成域名 ICP 备案 （服务器商控制台提交，约 1~3 周），否则 80/443 端口访问会被拦截。 小程序本身还要做「小程序备案」（第 8 章），两者是独立的，都要做。

第 2 步：申请免费 SSL 证书

推荐用云厂商的免费证书（一年期，可续），或 Let's Encrypt（90 天自动续）。 

# 以 Certbot (Let's Encrypt) 为例，Nginx 插件一条命令签发并自动配好
$ sudo apt install certbot python3-certbot-nginx
$ sudo certbot --nginx -d api.yourdomain.com
# 证书自动续期（测试续期是否正常）
$ sudo certbot renew --dry-run

企业/个人都可用云厂商（阿里云、腾讯云等）的「免费证书」：控制台申请 → 按提示做 DNS 验证 → 下载 Nginx 格式证书 → 手动上传服务器配置（见下一步）。

第 3 步：Nginx 配置 HTTPS 反向代理

假设你的后端监听 127.0.0.1:8000，Nginx 配置如下：

# /etc/nginx/sites-available/api.yourdomain.com
server {
    listen 443 ssl http2;
    server_name api.yourdomain.com;

    # 证书路径（certbot 会自动填；手动申请则写你自己的路径）
    ssl_certificate     /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.yourdomain.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;   # 小程序要求 TLS1.2+

    location / {
        proxy_pass         http://127.0.0.1:8000;
        proxy_set_header  Host $host;
        proxy_set_header  X-Real-IP $remote_addr;
        proxy_set_header  X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

# 80 端口跳转 HTTPS（可选但推荐）
server {
    listen 80;
    server_name api.yourdomain.com;
    return 301 https://$host$request_uri;
}

$ sudo ln -s /etc/nginx/sites-available/api.yourdomain.com /etc/nginx/sites-enabled/
$ sudo nginx -t                  # 先测配置，输出 syntax is ok 再继续
$ sudo systemctl reload nginx
⚠️ 别忘了安全组放行 443
云厂商安全组（防火墙）要放行 443 入方向，否则外面根本连不上。 这是「证书配好了还是连不上」的头号原因。

第 4 步：本机验证 HTTPS

$ curl https://api.yourdomain.com/api/health
# 期望：返回后端 JSON。若返回 HTML 502/504，看 Nginx error.log
$ sudo tail -f /var/log/nginx/error.log
# 验证证书链与 TLS（应显示 Verify return code: 0）
$ openssl s_client -connect api.yourdomain.com:443 -servername api.yourdomain.com

第 5 步：后台配置 request 合法域名

小程序后台 →「开发」→「开发管理」→「开发设置」→「服务器域名」→ request 合法域名，填入 https://api.yourdomain.com，保存。 保存后约 5~10 分钟生效，改完别急着测，先等一会儿。

第 6 步：前端代码切换正式地址

// 上线前把 baseURL 切到 https 正式域名
const { baseURL } = require('../../config')

wx.request({
  url: baseURL + '/api/health',
  success(res) {
    console.log('连通了：', res.data)
  },
  fail(err) {
    console.log('失败：', err)
  }
})

第 7 步：关掉跳过校验，完整回归

回到开发者工具「详情」→「本地设置」，取消勾选「不校验合法域名…」， 重新编译。此时请求仍成功，说明配置链路完整。再用真机关闭调试模式 验证一遍，这是最接近线上环境的测试。

本章常见问题

现象 原因 解决方法
报 url not in domain list 域名没配白名单 / 配错子域 / 刚配未生效 确认配的是 request 合法域名且子域完全一致；等 10 分钟；确认没勾跳过校验时测试
请求带 443 端口失败 配置域名不带端口时，请求 URL 也不能带端口 把 https://api.xxx.com:443 改成 https://api.xxx.com
报 errno 600001 / 证书无效 证书链不完整或证书与域名不匹配 nginx 配置 fullchain.pem；用 openssl 验证证书域名；iOS 不支持自签名证书
curl 通、小程序不通 curl 没走小程序的安全校验 重点查：域名是否备案、证书链、TLS 版本、是否带端口、白名单子域是否一致
服务器在国内却一直连不上 域名没备案被拦截 / 安全组没放行 确认域名 ICP 备案完成；安全组放行 443；curl -v 看卡在哪一步
真机开调试能通、关掉不通 正式环境强制域名校验，你的配置仍有问题 按六条铁律逐条核对（HTTPS/备案/无IP/无端口/子域精确/TLS1.2+）

07 云开发部署实战

云开发是个人开发者上线最快的方案：不用买服务器、不用配域名、 不用管 HTTPS——它在微信私有协议里跑，天然合法。数据量不大时成本几乎可以忽略。

第 1 步：开通并创建环境

  1. 开发者工具工具栏点「云开发」按钮，按提示开通（按量付费， 新环境通常有免费额度，具体以控制台显示为准）。
  2. 创建环境，得到一个环境 ID（形如 cloud1-xxxxxx）， 复制保存。环境 ID 写错是云开发第一坑。

第 2 步：前端初始化云能力

在 app.js 的 App() 里初始化（onLaunch 中执行一次）： 

// app.js
App({
  onLaunch() {
    if (!wx.cloud) {
      console.error('请使用 2.2.3 以上基础库以使用云能力')
    } else {
      wx.cloud.init({
        env: 'cloud1-xxxxxxxx',  // 换成你的环境 ID
        traceUser: true          // 追踪用户，方便控制台看调用者
      })
    }
  }
})

第 3 步：创建并部署云函数

  1. 项目根目录建 cloudfunctions/login 目录（工具模板可右键直接生成）。
  2. 云函数里写逻辑：index.js 导出 main，用 cloud.getWXContext() 拿用户 openid。
  3. 在 login 目录上右键 →「上传并部署：云端安装依赖」 （选这个而不是「上传所有文件」，避免缺 node_modules）。
  4. 控制台「云函数」里找到 login →「云端测试」，传 {} 应返回带 openid 的结果。 
// cloudfunctions/login/index.js（模板代码，可直接用）
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })  // 动态当前环境

exports.main = async (event, context) => {
  const { OPENID, APPID, UNIONID } = cloud.getWXContext()
  return { openid: OPENID, appid: APPID, unionid: UNIONID }
}

// 页面里调用云函数
wx.cloud.callFunction({
  name: 'login',
  success(res) {
    console.log('openid:', res.result.openid)
  },
  fail(err) {
    console.error('调用失败：', err)
  }
})

第 4 步：云数据库与云存储

控制台「数据库」创建集合（如 todos），权限按需设置—— 「仅创建者可读写」最常用，千万别图省事设成「所有用户可读」泄露别人数据： 

// 前端读写云数据库
const db = wx.cloud.database()
db.collection('todos').add({
  data: { title: '学习小程序部署', done: false, createTime: db.serverDate() }
}).then(console.log)

// 文件上传走云存储，返回 fileID 可直接用于 image 组件 src
wx.cloud.uploadFile({
  cloudPath: 'avatar/' + Date.now() + '.png',
  filePath: tmpFilePath
}).then(res => console.log(res.fileID))
💡 云开发免域名原理
云函数调用走微信私有协议，不走 wx.request，所以不需要配 request 合法域名， 也不需要自己的备案域名。这是它「最快上线」的根本原因。

本章常见问题

现象 原因 解决方法
报 errCode: -501000 / 环境不存在 wx.cloud.init 的 env 与环境 ID 不一致 到云开发控制台复制准确的环境 ID，重新初始化并编译
报 FunctionName 参数错误 / cloud function not found 云函数没部署成功，或名字拼错 确认控制台「云函数」列表里有该函数；右键「上传并部署」重新部署；检查 callFunction 的 name
调用云函数报超时 / timeout 默认超时短或函数里逻辑慢 控制台调大该函数超时时间（如 20s）；代码里避免同步等待长任务
数据库读写报权限错误（-502005） 集合权限太严或没建集合 控制台确认集合存在并已设置权限；创建者写、所有用户读等按需选
云开发控制台打不开 / 白屏 工具与云开发控制台兼容问题 换 Chrome 浏览器访问控制台 URL；或更新开发者工具到最新稳定版
免费额度用尽后接口报错 资源超限 控制台看用量与账单；可升级套餐，或优化云函数调用频次、数据库读写量

08 上架前四件套：备案 / 隐私 / 类目 / 体验版

代码写完别急着上传——先把下面四件事办完，否则审核必被驳回，白等好几天。

① ICP 小程序备案（不备案无法发布）

2023 年 9 月起，所有小程序（含个人）上架前必须完成小程序备案。 全程在微信后台操作、免费。个人备案材料只需身份证 + 手机号 + 应急联系人。

  1. 登录 mp.weixin.qq.com → 顶部「去备案」横幅， 或「设置」→「基本设置」→ 备案信息 →「去备案」。
  2. 填写主体信息（个人：姓名 / 身份证 / 手机号 / 应急联系人，应急联系人手机号不能与本人重复） → 填写小程序信息（名称自动带出，服务内容描述写清楚干什么，50~200 字）。
  3. 提交后人脸核验：用手机微信扫页面二维码，按提示完成人脸识别。
  4. 等待审核：平台初审（1~2 个工作日）→ 收到 12381 短信后， 24 小时内登录 beian.miit.gov.cn 点短信核验 （超时自动驳回！）→ 管局审核（1~20 个工作日，通常 1~2 周）。
节点 耗时（参考） 注意
信息填写 + 人脸核验 1 天 所有材料信息必须与身份证完全一致
平台初审 1~2 个工作日 材料问题会打回，按驳回提示改
短信核验 收到短信后 24 小时内 漏了直接驳回，需重新提交
管局审核 5~20 个工作日 各省速度不同
⚠️ 备案期间能做什么
备案和代码开发、提交微信内容审核互相不阻塞——备案走流程的同时， 你完全可以继续开发、上传代码、提交审核。别傻等备案。

② 用户隐私保护指引

小程序只要涉及收集用户信息（头像昵称、手机号、位置、相册、麦克风等），就必须在后台声明 《小程序用户隐私保护指引》，否则隐私接口调用会失败，审核也会被驳回。

  • 后台路径：「设置」→「服务内容声明」→「用户隐私保护指引」→ 按实际勾选 收集的信息类型并填写用途。
  • 声明要与你代码里实际调用的隐私接口一致：勾少了接口被禁，勾多了审核质疑。
  • 2023 年 9 月 15 日后，隐私接口调用前需先弹隐私授权弹窗 （wx.requirePrivacyAuthorize / 组件触发），首次启动建议先引导用户同意再进主流程。

③ 类目与资质自查

检查项 要求
类目与功能一致 实际提供什么服务就选什么类目，无隐藏类目
主体支持该功能 个人主体不能做支付交易、AI 对话（深度合成）等
特殊行业资质 新闻、医疗、金融、教育等需前置审批文件
名称 / 头像 / 简介 三者与实际功能相符，无违禁词、无侵权
核心功能在首页体现 审核员打开首页就能看懂你的小程序是干嘛的

④ 体验版真机回归

开发者工具点「上传」（填版本号如 1.0.0 + 项目备注）→ 后台 「管理」→「版本管理」→ 开发版本里点「设为体验版」→ 生成体验二维码 → 发给自己和体验成员扫码测试。

🚫 提交审核前，务必用体验版做一次「无调试模式」回归
① 手机关闭「开发调试」；② 把首页到核心功能完整走一遍； ③ 重点验证网络请求、登录授权、支付（如有）。线上 90% 的「白屏 / 请求失败」， 都是因为只测了开发版（跳过了域名校验），体验版一测就现形。

09 上传代码与提交审核

上传代码（开发者工具 → 微信服务器）

  1. 确认 AppID 是你自己的、右上角头像是你（管理员/开发者身份）。
  2. 工具栏点「上传」→ 填版本号 （建议语义化：首次 1.0.0，小改 1.0.1，新功能 1.1.0）和项目备注 （本次改了什么，方便以后回溯）。
  3. 上传成功后，登录小程序后台 →「管理」→「版本管理」，在开发版本 列表能看到刚上传的版本。
💡 版本号规范建议
主版本.次版本.修订号：1.0.0 首次发布；1.0.x 修 bug； 1.x.0 加功能。版本号只增不减，后台不能重复用已存在的版本号。

提交审核

  1. 版本管理页，开发版本右侧点「提交审核」。
  2. 填写审核信息：功能页面（勾选需要审核的核心页面）、 测试账号（如果小程序需要登录，务必提供可用的测试账号密码并写清使用步骤， 否则审核员进不去，直接驳回）、阅读并同意《小程序用户隐私保护指引》。
  3. 提交后进入审核中状态，常规 1~7 天。 企业主体完成微信认证后有加急审核额度（重要更新可用，个人主体没有）。
⚠️ 审核期间还能改代码吗
能改，但已提交的审核版本不受影响（审的是你提交那一刻的代码）。 如需改动，改完重新上传新版本，在开发版本里再次提交审核即可，旧审核会自动作废或继续（以后台状态为准）。

审核驳回：高频原因与应对

驳回原因（常见话术） 真实问题 解决方法
「类目与页面功能不符」 实际功能超出所选类目 / 主体 换与功能匹配且主体支持的类目；功能超主体权限的只能砍功能或换主体
「无法完整体验」/「需登录才能使用」 没提供测试账号，或功能流程走不通 提交审核时填测试账号 + 操作指引；保证核心流程无付费墙也能体验
「涉及诱导分享」 强制分享后才能用 / 利益诱导分享 去掉「分享解锁」「分享领红包」类逻辑；分享需用户自愿
「名称 / 简介与实际功能不符」 标题党或简介夸大 改名（注意次数限制）或改简介，做到名实相符
「涉及用户隐私未声明」 收集信息没配隐私指引 / 弹窗缺失 按第 8 章补齐隐私声明；首次启动先弹隐私授权
「功能过于简单 / 同质化严重」 内容单薄或与已有小程序雷同 补充有价值的功能模块，做出差异化的核心能力
「含有测试 / 占位内容」 页面留了「测试中」「TODO」或假数据 上线前清理所有占位内容、测试按钮、console 广告信息
「无法打开 / 白屏」 正式环境请求失败（域名/证书），或 JS 报错 体验版关闭调试模式回归；查 Console 与 Network；按第 6 章核对域名

被驳回不用慌：驳回通知里会写明原因和修改建议，改完重新上传 → 再提交审核即可。 同一版本反复驳回不影响账号。

10 发布与版本管理

审核通过后发布

审核通过状态为「审核通过」，此时还没上线。去版本管理 → 「审核版本」→ 点「发布」，选择发布方式：

发布方式 说明 适用
全量发布 所有用户立即使用新版本 首次上线、小改动、紧急修复
分阶段发布（灰度） 先给 5%→10%→…→100% 用户，逐步放量，异常可中途停止 大版本更新（需企业认证，个人主体一般直接全量）

发布后版本生命周期

开发者工具上传 ──> 开发版本
                  ├── 设为体验版 ──> 体验版（内部测试）
                  └── 提交审核 ──> 审核中
                              ├── 驳回 ──> 修改后重新上传
                              └── 通过 ──> 审核版本
                                          └── 发布 ──> 线上版本（全量 / 灰度）
                                                      └── 出问题 ──> 回退到上一线上版本

线上出 bug 了：回滚优先于修 bug

发布后发现严重问题，第一反应不是改代码，而是先止血：

  1. 版本管理 →「线上版本」→ 当前版本右侧「回退」， 可一键回到上一个线上版本（回退需谨慎确认，会立即全量生效）。
  2. 止血后，在本地修 bug → 上传新版本（版本号递增）→ 提交审核 → 通过后重新发布。 修复期间旧版本（回退后的版本）始终在服务用户。
🚫 三个发布禁忌
① 不要在深夜 / 节假日发布大版本（出问题没人及时响应）； ② 不要用同一个版本号重复上传（后台不允许且易混淆）； ③ 不要跳过体验版直接全量——至少自己扫码把主流程走一遍。

暂停服务 / 下架

后台「设置」→「基本设置」→ 功能设置里有「暂停服务」选项（主动下架）。 注意：个人小程序长期不使用不会自动下架，但若违反运营规范被下架，整改后可重新提审。

本章常见问题

现象 原因 解决方法
审核通过但找不到「发布」按钮 入口在版本管理的「审核版本」页 「管理」→「版本管理」→ 上方切到「审核版本」标签 → 点发布
上传时提示版本号已存在 该版本号之前上传过 换一个更高版本号（如 1.0.0 已用则用 1.0.1）
找不到分阶段发布入口 个人主体 / 未认证企业不支持 个人主体直接全量发布；企业需先完成微信认证
回退后用户还是旧版本 微信客户端有本地缓存 回退是服务端生效，客户端会自动拉新；个别用户可让其在「···」里手动刷新版本
新版本审核期间老版本挂了 老版本本身有 bug，与新版本无关 回退到更早的稳定线上版本；新版本走加急审核（企业认证可用）

日常要盯的三个数据入口

入口 位置 看什么
小程序后台数据 后台左侧「统计」 访问人数、打开次数、来源渠道、页面停留——判断功能受不受欢迎

自己代码里的监控三板斧

  • 全局捕获 JS 错误：在 app.js 里监听 wx.onError， 把错误上报到自己的后端或云函数，形成错误日志库。
  • 接口耗时埋点：封装 wx.request 时统一记录 url / statusCode / 耗时， 慢接口会在数据里自己浮出来。
  • 后端日志 + 告警：自建后端看 Nginx access/error 日志与业务日志； 云开发在控制台「云函数」→ 日志里查调用链。云开发还支持配置 告警策略（如调用失败率超阈值触发）。 
// app.js：全局错误上报（云开发示例）
if (wx.onError) {
  wx.onError(err => {
    wx.cloud.callFunction({
      name: 'reportError',
      data: { msg: err.message, stack: err.stack, page: getCurrentPages().slice(-1)[0]?.route }
    }).catch(console.error)
  })
}

迭代发布 SOP（每周发版不慌）

  1. 改代码：本地跑通，Console 无报错。
  2. 体验版自测：上传 → 设体验版 → 关闭调试模式真机回归主流程。
  3. 提交审核：填好功能页面与测试账号；大版本走灰度发布。
  4. 通过后择时发布：避开高峰与深夜，灰度先放 5%~10% 观察半小时。
  5. 盯数据：发布后 1 小时内看错误率与用户反馈，异常立即回滚。
  6. 记录版本：版本号 + 备注写清楚改动，方便回溯（同第 9 章规范）。
💡 别忘了小程序账号的安全
① AppSecret 只能存在你自己的服务器里，绝不能写进前端代码或仓库； ② 后台「开发设置」可为 access_token 接口配 IP 白名单； ③ 团队成员离职及时在「成员管理」里移除；④ 定期重置 Secret。

全书高频报错速查

报错 / 现象 原因 一句话解决
url not in domain list 域名未配白名单或请求带端口/IP 后台配 request 合法域名；URL 不带端口不带 IP
request:fail 无法连接 / errno 600002 域名没备案、证书问题或服务没起 curl 直连排查；查备案、证书链、TLS1.2+、安全组 443
errno 600001 证书无效 证书链不完整 / 域名不匹配 / 自签名 配 fullchain.pem；iOS 不认自签名证书
AppID 无效 / 登录后无项目 appid 填错或非项目成员 填自己 AppID；后台成员管理加为开发者
编译报 app.json not found 导入目录层级不对 目录指向含 app.json 的那一层
-501000 云环境不存在 wx.cloud.init env 写错 控制台复制准确环境 ID
cloud function not found（-501000 系列） 云函数未部署 / 名字拼错 右键「上传并部署：云端安装依赖」
-502005 数据库无权限 集合权限设置问题 控制台按业务设置集合读写权限
getUserProfile / getLocation 调用失败 隐私指引未声明或未弹窗授权 后台配《用户隐私保护指引》；先 wx.requirePrivacyAuthorize
真机扫码打开白屏 开发版正常但正式环境域名校验失败 体验版关调试模式回归；按第 6 章六条铁律排查
页面提示「不在以下 request 合法域名列表中」 调试开关已关 把该域名加入白名单后等 10 分钟再试
预览二维码扫了没反应 过期 / 非成员 刷新二维码；用管理员微信扫
审核被驳回「无法完整体验」 没给测试账号或流程不通 提审时附测试账号与使用说明
发布后用户仍是旧版本 客户端缓存 服务端生效即可；极端情况引导用户手动刷新

首次上线：8 步最终验证清单

  1. 备案完成：后台备案状态「已备案」，展示备案号。
  2. 后端可达：curl 通 https，小程序正式域名在白名单。
  3. 隐私指引已配置，首次启动弹窗授权正常。
  4. 体验版关调试模式：首页打开、接口返回正常、无红屏报错。
  5. 核心链路完整：登录/注册、列表、下单（如有支付）、分享逐项走通。
  6. 提审信息齐全：功能页面已勾选，测试账号已填。
  7. 发布后 1 小时盯数据：错误率无异常、核心接口失败率为 0。
  8. 告警通道就绪：已关注「微信小程序助手」，后端/云开发告警已配。

十句口诀总结

📝 部署全流程口诀

① 先注册后备案，备案最久别偷懒；
② AppID 是身份证，复制保存记心间；
③ 模拟器只是参考，真机回归才算数；
④ 跳过校验是开发，正式环境必校验；
⑤ HTTPS 加备案，IP 端口泛域名都不沾；
⑥ 没服务器走云开发，免域名免运维最快上线；
⑦ 隐私指引先声明，弹窗授权要先行；
⑧ 测试账号给审核员，功能走通才过审；
⑨ 版本号只增不减，线上出 bug 先回滚；
⑩ 发布之后盯数据，告警在手心不慌。
