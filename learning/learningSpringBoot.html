01入门篇

01Spring Boot 生态与第一个应用

📖 Spring 生态全景

Spring 是一个轻量级的 Java 企业级应用开发框架，通过 IoC（控制反转）和 AOP（面向切面）解耦业务，让开发者专注业务逻辑而非基础设施。

Spring Boot 是 Spring 的"脚手架"——通过约定优于配置，帮你自动装配 Bean、内嵌 Tomcat、提供 starter 依赖，让 5 分钟跑起一个 Web 应用。

Spring Cloud 是基于 Spring Boot 的微服务全家桶（网关/配置中心/服务发现/熔断/链路追踪）。

Spring 家族成员速览

组件 作用 一句话定位
Spring Framework 核心容器（IoC/AOP/MVC/事务） 企业级 Java 的"地基"
Spring Boot 脚手架 + 自动装配 + 内嵌容器 5 分钟跑起一个应用
Spring Data 数据访问抽象（JPA/MongoDB/Redis） 统一持久层 API
Spring Security 认证授权与安全防护 OAuth2/JWT/CAS 全支持
Spring Cloud 微服务架构套件 分布式系统的"瑞士军刀"
Spring AI LLM 应用开发框架 Java 接入大模型的官方方案
🧠 Spring Boot 四大核心特性
  1. 自动装配（Auto-Configuration）：根据 classpath 里的 jar 自动配置 Bean
  2. 起步依赖（Starter）：一站式引入相关依赖，避免版本冲突
  3. 内嵌容器：内置 Tomcat/Jetty/Undertow，无需部署 WAR
  4. 外部化配置：支持 yml/properties/env/命令行等多源配置

5 分钟创建第一个 Spring Boot 应用

方式一：Spring Initializr（推荐）。访问 https://start.spring.io，选择：

  • Project: Maven（或 Gradle）
  • Language: Java
  • Spring Boot: 3.3.x（最新稳定版）
  • Group: com.example，Artifact: demo
  • Dependencies: Spring Web
  • 点击 Generate 下载 zip，解压导入 IDE 即可

方式二：命令行（curl 一行创建）

curl https://start.spring.io/starter.zip \
  -d type=maven-project \
  -d language=java \
  -d bootVersion=3.3.4 \
  -d baseDir=demo \
  -d groupId=com.example \
  -d artifactId=demo \
  -d dependencies=web \
  -o demo.zip
unzip demo.zip

方式三：IDE 向导。IDEA → New Project → Spring Initializr → 一路下一步。

Hello World 三步走

第 1 步：主启动类（带 @SpringBootApplication） 

package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication   // 等价于 @Configuration + @EnableAutoConfiguration + @ComponentScan
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

第 2 步：写一个 Controller

package com.example.demo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController   // @Controller + @ResponseBody：返回 JSON 而不是视图
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello, Spring Boot!";
    }
}

第 3 步：运行。在 IDE 里运行 DemoApplication.main()，或命令行 ./mvnw spring-boot:run。访问 http://localhost:8080/hello 即可看到结果。

⚠️ 高频坑：主类必须放在根包下

主类 DemoApplication 必须位于"根包"（如 com.example.demo），这样 @ComponentScan 默认扫描 com.example.demo 及其所有子包，否则你的 Controller/Service 不会被注册。

📌 第 1 章速记口诀

Spring 是地基，Boot 是脚手架，Cloud 是分布式套件；主类放根包，启动三步走（注解+Controller+运行），5 分钟跑通 hello world。

02Maven/Gradle 与项目搭建

📖 构建工具选型

Spring Boot 同时支持 Maven 和 Gradle。国内用 Maven 居多（生态成熟、IDEA 内置），Gradle 在云原生/Android/Kotlin 项目更主流。

Maven vs Gradle 对比

维度 Maven Gradle
配置语言 XML（pom.xml） Groovy/Kotlin DSL（build.gradle）
构建速度 中等（增量构建） 快（增量 + 任务并行）
依赖管理 自动传递依赖（可能冲突） 可精细控制版本
学习曲线 低 中
适用场景 传统 Java EE 项目 大型/Android/Kotlin 项目

pom.xml 关键结构（Spring Boot 3.x）

<?xml version="1.0" encoding="UTF-8"?>

    <parent>

    <artifactId>demo</artifactId>
    <version>0.0.1-SNAPSHOT</version>

        <java.version>17</java.version>
        <maven.compiler.source>17</maven.compiler.source>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <dependencies>
        <!-- Web 起步依赖：一站式引入 Spring MVC + Tomcat + JSON -->
        <dependency>
            <groupId>org.springframework.boot</groupId>

        </dependency>

        <!-- 测试起步依赖 -->

    <build>

            <!-- 打包插件：生成可执行 fat jar -->
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>

        </plugins>

</project>

📖 Spring Boot 配置来源（优先级从高到低）

读取配置的 4 种方式

方式 1：@Value（单个值）

@RestController
public class AppController {
    @Value("${server.port}")
    private Integer port;

    @Value("${myapp.jwt.expire:86400}")   // 默认值 86400
    private Long jwtExpire;

    @GetMapping("/port")
    public String port() { return "port=" + port; }
}

方式 2：@ConfigurationProperties（推荐批量绑定） 

@Configuration
@ConfigurationProperties(prefix = "myapp.jwt")   // 绑定 ymyapp.jwt.* 配置
@Data   // Lombok 自动生成 getter/setter
public class JwtProperties {
    private String secret;
    private Long expire = 86400L;
}

// 启用：@EnableConfigurationProperties(JwtProperties.class)
// 或在主类加 @ConfigurationPropertiesScan

方式 3：Environment（代码里读）

@Autowired
private Environment env;

String secret = env.getProperty("myapp.jwt.secret");

方式 4：${...} 占位符 

app:
  name: ${spring.application.name}-v2   # 引用其他配置
  desc: ${app.desc:默认描述}             # 带默认值

Profile 多环境配置

企业项目通常有 dev/test/prod 三套环境：

# application.yml（公共）
spring:
  profiles:
    active: dev   # 默认激活 dev

# application-dev.yml（开发）
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo_dev

# application-prod.yml（生产）
server:
  port: 80
spring:
  datasource:
    url: jdbc:mysql://prod-mysql:3306/demo

激活方式：

  • yml 里 spring.profiles.active=prod
  • 命令行：java -jar demo.jar --spring.profiles.active=prod
  • 环境变量：SPRING_PROFILES_ACTIVE=prod
  • JVM：-Dspring.profiles.active=prod
⚠️ yml 五大坑
  1. 缩进必须用空格，不能用 Tab
  2. key:value 之间必须有空格：name: 张三 ✅，name:张三 ❌
  3. 字符串可不加引号，但含特殊字符（: # 等）必须引号
  4. 多文档用 --- 分隔
  5. 数值/布尔自动转换：port: "8080" 是字符串，port: 8080 是数字
📌 第 3 章速记口诀

yml 缩进空格不能 Tab，key 冒号后必须空格；批量配置用 @ConfigurationProperties 绑定前缀，单值用 @Value；profile 多环境靠文件名 application-{name}.yml 区分。

04Web 开发与 RESTful 接口

📖 Spring MVC vs Spring WebFlux

Spring Boot 同时支持两种 Web 栈：

  • Spring MVC（Servlet）：同步阻塞，每个请求一个线程，生态最广，推荐默认
  • Spring WebFlux（Reactive）：响应式非阻塞，基于 Netty，适合高并发 IO 密集型场景

完整 CRUD 示例

@RestController
@RequestMapping("/api/users")
public class UserController {

    @Autowired
    private UserService userService;

    @GetMapping
    public List<User> list() {
        return userService.findAll();
    }

    @GetMapping("/{id}")
    public User getById(@PathVariable Long id) {
        return userService.findById(id);
    }

    @PostMapping
    public User create(@RequestBody @Valid User user) {
        return userService.save(user);
    }

    @PutMapping("/{id}")
    public User update(@PathVariable Long id, @RequestBody User user) {
        user.setId(id);
        return userService.update(user);
    }

    @DeleteMapping("/{id}")
    public void delete(@PathVariable Long id) {
        userService.deleteById(id);
    }
}

统一响应格式

企业级接口通常封装统一返回：

@Data
public class Result<T> {
    private Integer code;       // 状态码
    private String message;     // 提示信息
    private T data;             // 业务数据
    private Long timestamp = System.currentTimeMillis();

    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.code = 200;
        r.message = "OK";
        r.data = data;
        return r;
    }

    public static <T> Result<T> error(Integer code, String message) {
        Result<T> r = new Result<>();
        r.code = code;
        r.message = message;
        return r;
    }
}

常用状态码

状态码 含义
200 成功
400 请求参数错误
401 未登录/token 过期
403 无权限
404 资源不存在
500 服务器内部错误
503 服务不可用
💡 Spring MVC 工作流程（八步）
  1. DispatcherServlet 接收请求
  2. 调用 HandlerMapping 找到对应 Controller 方法
  3. 调用 HandlerAdapter 执行方法
  4. 方法参数解析（@RequestBody/@PathVariable 等）
  5. 执行业务逻辑，返回值被包装为 ModelAndView
  6. ViewResolver 解析视图
  7. 视图渲染（对 @RestController 直接写 JSON）
  8. 响应返回客户端
📌 第 4 章速记口诀

@RestController 走 JSON，统一 Result<T> 包装响应；RESTful 用 HTTP 方法区分增删改查（GET/POST/PUT/DELETE），状态码 200/400/401/403/404/500 一一对应。

05数据持久化：JDBC/JPA/MyBatis

📖 Spring Data 三剑客
  • Spring JDBC：JdbcTemplate，简化 JDBC 代码，仍需手写 SQL
  • Spring Data JPA：基于 Hibernate ORM，面向对象操作数据库（适合复杂业务）
  • MyBatis：面向 SQL，XML/注解写 SQL，灵活可控（国内最主流）
  • Spring Data Redis/MongoDB/Elasticsearch：NoSQL 抽象

三种持久化方案对比

维度 JdbcTemplate Spring Data JPA MyBatis
SQL 控制 完全 部分（复杂需 @Query） 完全
学习曲线 低 高（HQL/JPQL） 低
动态 SQL 手写拼接 Specification XML 标签（强大）
国内使用率 少 中（外企） ★★★★★
适用场景 简单 CRUD/报表 领域模型复杂 SQL 复杂/性能敏感

1）添加依赖

<dependency>

2）实体类

@Entity
@Table(name = "t_user")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 50)
    private String username;

    @Column(unique = true)
    private String email;

    @Column(name = "create_time")
    private LocalDateTime createTime = LocalDateTime.now();
}

3）Repository 接口（无需实现类）

public interface UserRepository extends JpaRepository<User, Long> {

    // 方法名派生查询
    Optional<User> findByUsername(String username);

    boolean existsByEmail(String email);

    // 自定义 JPQL
    @Query("SELECT u FROM User u WHERE u.createTime > :time")
    List<User> findRecentUsers(@Param("time") LocalDateTime time);
}

4）Service 调用

@Service
public class UserService {
    @Autowired
    private UserRepository repo;

    @Transactional
    public User save(User user) {
        return repo.save(user);
    }
}

public interface UserMapper {
    User findById(Long id);
    List<User> findAll();

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.demo.mapper.UserMapper">
    <resultMap id="userMap" type="User">
        <id property="id" column="id"/>
        <result property="username" column="username"/>
        <result property="createTime" column="create_time"/>
    </resultMap>

    <select id="findById" resultMap="userMap">
        SELECT * FROM t_user WHERE id = #{id}
    </select>

    <!-- 动态 SQL -->
    <select id="findAll" resultMap="userMap">
        SELECT * FROM t_user
        <where>
            <if test="keyword != null and keyword != ''">
                AND username LIKE CONCAT('%', #{keyword}, '%')
            </if>
        </where>
        ORDER BY create_time DESC
    </select>

    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO t_user(username, email, create_time)
        VALUES (#{username}, #{email}, #{createTime})
    </insert>
</mapper>

事务管理（@Transactional）

@Service
public class OrderService {
    @Autowired
    private OrderRepository orderRepo;
    @Autowired
    private StockService stockService;

    @Transactional   // 整个方法在一个事务里
    public Order createOrder(Order order) {
        order = orderRepo.save(order);
        stockService.deduct(order);   // 任一异常会整体回滚
        return order;
    }

    @Transactional(propagation = Propagation.REQUIRED,    // 默认：加入已有事务或新建
                   isolation = Isolation.READ_COMMITTED,  // 读已提交
                   rollbackFor = Exception.class,        // 所有异常都回滚（默认仅 RuntimeException）
                   timeout = 30)                          // 30 秒超时
    public void critical() { ... }
}
传播行为 含义
REQUIRED（默认） 有则加入，无则新建
REQUIRES_NEW 始终新建，暂停外层
NESTED 嵌套事务（保存点）
SUPPORTS 有则加入，无则非事务
NEVER 有事务则抛异常
⚠️ @Transactional 五大坑
  1. 只能用在 public 方法上
  2. 同类内方法互调不生效（因为是代理对象调用）
  3. 异常被 try-catch 吞掉不会回滚
  4. 默认仅对 RuntimeException 回滚，checked 异常不回滚（用 rollbackFor = Exception.class 解决）
  5. Spring Bean 的创建顺序问题：A 依赖 B，B 调 A 的事务方法不生效
📌 第 5 章速记口诀

JPA 面向对象自动生成 SQL，MyBatis 面向 SQL 灵活可控；@Transactional 默认 REQUIRED 传播+读已提交隔离，public 方法上才能生效，同类自调用失效。

06服务分层：Controller/Service/Repository

📖 为什么分层？

分层是为了解耦：

  • 可维护：改一处不影响全局
  • 可测试：每层独立单元测试
  • 可扩展：换实现不改接口
  • 可协作：团队各负责一层

三层架构与四层架构

层 职责 注解 依赖关系
Controller（表现层） 接收请求/参数校验/返回响应 @RestController 调 Service
Service（业务层） 核心业务逻辑/事务控制/编排 @Service 调 Repository + 其他 Service
Repository/Mapper（持久层） 数据库读写/外部接口调用 @Repository / @Mapper 调 DB
Entity/PO（领域对象） 与数据库表一一映射 @Entity 无依赖
DTO（传输对象） Controller ↔ Service 间传输 — —
VO（视图对象） Controller → 前端展示 — —

POJO 三大对象

对象 全称 用途 字段对应
PO / Entity Persistent Object 持久化，与表一一对应 DB 字段
DTO Data Transfer Object 服务间数据传输 业务字段
VO View Object 前端展示 展示字段
BO Business Object 复杂业务封装 组合多个 PO

📖 为什么需要全局异常处理？

没有统一处理时，每个 Controller 都要写 try-catch，重复且容易遗漏；有了 @RestControllerAdvice + @ExceptionHandler，可以集中捕获并返回统一格式。

@Data
public class Result<T> implements Serializable {

    private String message;
    private T data;
    private Long timestamp = System.currentTimeMillis();

        this.code = code;
        this.message = message;
        this.data = data;

    public static <T> Result<T> success() { return new Result<>(200, "OK", null); }

全局异常处理器

@RestControllerAdvice   // = @ControllerAdvice + @ResponseBody
@Slf4j
public class GlobalExceptionHandler {

    // 1. 业务异常
    @ExceptionHandler(BizException.class)
    public Result<?> handleBiz(BizException e) {
        log.warn("业务异常：{}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    // 2. 参数校验异常（@Valid 失败）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValid(MethodArgumentNotValidException e) {
        FieldError fieldError = e.getBindingResult().getFieldError();
        String msg = fieldError != null ? fieldError.getDefaultMessage() : "参数校验失败";
        return Result.error(400, msg);
    }

    // 3. 请求方式不支持
    @ExceptionHandler(HttpRequestMethodNotSupportedException.class)
    public Result<?> handleMethod(HttpRequestMethodNotSupportedException e) {
        return Result.error(405, "不支持 " + e.getMethod() + " 请求");
    }

    // 4. 兜底：所有未捕获异常
    @ExceptionHandler(Exception.class)
    public Result<?> handleAll(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "服务器内部错误：" + e.getMessage());
    }
}

统一返回包装（可选）

如果想偷懒让所有 Controller 默认返回 Result，可以用 ResponseBodyAdvice： 

@RestControllerAdvice
public class ResponseWrapper implements ResponseBodyAdvice<Object> {

    @Override
    public boolean supports(MethodParameter returnType, Class<? extends HttpMessageConverter<?>> converterType) {
        // 已包装的 Result 不再二次包装
        return !returnType.getParameterType().equals(Result.class);
    }

    @Override
    public Object beforeBodyWrite(Object body, MethodParameter returnType, MediaType selectedContentType,
                                  Class<? extends HttpMessageConverter<?>> selectedConverterType,
                                  ServerHttpRequest request, ServerHttpResponse response) {
        if (body == null) return Result.success();
        if (body instanceof String || body instanceof Result) return body;
        return Result.success(body);
    }
}
⚠️ String 返回值包装陷阱

如果 Controller 返回 String，会被当成视图名直接写出，不会经过 ResponseBodyAdvice 的 JSON 序列化路径。需要判断后直接 return body，或把 String 改为返回 Result<String>。

缓存穿透 查不存在的数据，每次都打到 DB 布隆过滤器、缓存空对象

JWT 工具类

@Component
public class JwtUtil {
    @Value("${myapp.jwt.secret}")
    private String secret;
    @Value("${myapp.jwt.expire}")
    private Long expire;

    private static final String HEADER = "Authorization";
    private static final String PREFIX = "Bearer ";

    public String generate(Long userId, String username) {
        return Jwts.builder()
            .setSubject(String.valueOf(userId))
            .claim("username", username)
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + expire * 1000))
            .signWith(SignatureAlgorithm.HS256, secret)
            .compact();
    }

    public Claims parse(String token) {
        return Jwts.parser().setSigningKey(secret).parseClaimsJws(token).getBody();
    }
}

JWT 过滤器

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Autowired
    private JwtUtil jwtUtil;

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse resp, FilterChain chain)
            throws ServletException, IOException {
        String header = req.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            try {
                Claims claims = jwtUtil.parse(token);
                Long userId = Long.valueOf(claims.getSubject());
                String username = (String) claims.get("username");

                UsernamePasswordAuthenticationToken auth =
                    new UsernamePasswordAuthenticationToken(username, null, Collections.emptyList());
                SecurityContextHolder.getContext().setAuthentication(auth);
            } catch (Exception e) {
                resp.setStatus(401);
                resp.getWriter().write("token 无效");
                return;
            }
        }
        chain.doFilter(req, resp);
    }
}

13响应式编程（WebFlux/Reactor）

📖 同步 vs 异步 vs 响应式
  • 同步阻塞：调用方等被调方执行完才继续（Spring MVC）
  • 异步非阻塞：调用方发起调用后继续做其他事（CompletableFuture）
  • 响应式：基于事件流 + 背压机制，数据可用时推送（Reactor / RxJava）

Reactor 核心类型

类型 数据量 类似 Java 9+
Mono 0 或 1 个元素 Optional / CompletableFuture<T>
Flux 0 到 N 个元素 Stream<T> / List<T>

MVC vs WebFlux 对比

维度 Spring MVC Spring WebFlux
并发模型 每请求一线程 事件循环（少量线程）
适用场景 关系型 DB / CPU 密集 NoSQL / IO 密集

生态成熟度 ★★★★★ ★★★
推荐场景 99% 项目 高并发 IO 密集型
⚠️ WebFlux 五大坑
  1. 不能调用阻塞 IO（JDBC、RestTemplate），否则事件循环被卡死
  2. JDBC 用 JdbcTemplate 会阻塞，需用 R2DBC
  3. 学习曲线陡峭，调试困难，新手慎入
  4. 并非"响应式就一定快"，CPU 密集场景反而更慢
  5. 不能直接返回 Flux<Void> 收尾（不会真正发完）
💡 何时该用 WebFlux？
  • 网关聚合多个后端 API（高并发 IO 密集）
  • 推送服务（股票报价、聊天消息）
  • 微服务内部通信（Spring Cloud Gateway 默认 WebFlux）
  • 不推荐：传统业务 CRUD、CPU 密集、SQL 复杂查询

📖 Spring Boot 自动装配魔法

为什么加了 spring-boot-starter-web 就自动配置好 Tomcat + Spring MVC？为什么加了 spring-boot-starter-data-jpa 就自动配置好 Hibernate + DataSource？自动装配（Auto-Configuration）是 Spring Boot 的核心魔法。

Spring Boot 启动流程（九步）

1. new SpringApplication(primarySources)
2. 推断应用类型（Servlet/Reactive）
3. 加载所有 META-INF/spring.factories（或 spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports）
4. 实例化 ApplicationContext
5. refresh() 触发 Bean 创建
6. 执行 AutoConfigurationImportSelector 加载自动配置类
7. 按 @Conditional 注解筛选生效配置
8. 创建并注册 Bean
9. 启动 Web 服务器（Tomcat/Netty）

核心注解

注解 作用
@SpringBootApplication 三合一：@Configuration + @EnableAutoConfiguration + @ComponentScan
@EnableAutoConfiguration 开启自动装配（通过 @Import 引入 AutoConfigurationImportSelector）
@ConditionalOnClass classpath 里有指定类才生效
@ConditionalOnMissingBean 容器里没有指定 Bean 才生效
@ConditionalOnProperty 配置项匹配才生效
@ConditionalOnWebApplication Web 应用才生效
@AutoConfigureBefore / @AutoConfigureAfter 指定配置顺序

2）HelloProperties（配置绑定）

@Data
@ConfigurationProperties(prefix = "myapp.hello")
public class HelloProperties {
    private String prefix = "Hello";
    private String suffix = "!";
}

3）HelloService（业务 Bean）

public class HelloService {
    private final HelloProperties properties;

    public HelloService(HelloProperties properties) {
        this.properties = properties;
    }

    public String sayHello(String name) {
        return properties.getPrefix() + ", " + name + properties.getSuffix();
    }
}

4）HelloAutoConfiguration（自动配置类）

@AutoConfiguration
@ConditionalOnClass(HelloService.class)
@EnableConfigurationProperties(HelloProperties.class)
public class HelloAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean   // 用户没自定义才用默认
    public HelloService helloService(HelloProperties props) {
        return new HelloService(props);
    }
}

⚠️ 微服务三大陷阱
  1. 分布式事务：跨服务数据一致性问题（用 Seata）
  2. 服务雪崩：一个服务挂掉拖垮全链路（用熔断 + 限流）

💡 何时该用微服务？
  • 用：团队 > 10 人、业务复杂、并发高、独立扩展需求
  • 不用：初创项目、单一业务、团队小 —— 单体先行，微服务是演进不是设计

30 大高频坑（按模块）

1）启动/配置（10 大坑）

1. 主类不在根包 → Controller 未被扫描
2. yml 用 Tab 缩进 → 启动失败
3. key 冒号后漏空格 → 配置读不到
4. 端口被占用 → 改 server.port
5. 中文配置乱码 → 设 charset=UTF-8
6. 同一配置多处定义 → 优先级混乱
7. @Value 无默认值 → 配置缺失启动失败
8. profile 文件名拼错 → 不生效
9. 配置项大小写敏感 → user.name 和 username 不同
10. jar 包冲突 → 用 mvn dependency:tree 排查

2）数据/事务（10 大坑）

1. @Transactional 加 private 方法 → 不生效
2. 同类自调用（A.this.b()）→ 事务失效
3. 异常被 catch 吞了 → 事务不回滚
4. checked 异常不回滚 → 加 rollbackFor = Exception.class
5. MyBatis 找不到 Mapper → @MapperScan 或 @Mapper
6. SQL 没传参 → 用 #{} 不是 ${}
7. 大事务 → 拆分方法
8. 循环里单条插入 → 批量插入
9. N+1 查询 → 用 join 或 @EntityGraph
10. 不关连接 → 配置连接池超时

3）Web/安全（10 大坑）

1. CSRF 未关（前后端分离）→ .csrf().disable()
2. JWT 密钥硬编码 → 用配置中心
3. token 不过期 → 必须设 expire
4. 跨域报错 → 加 CorsFilter 或 @CrossOrigin
5. 文件上传大小限制 → spring.servlet.multipart.max-file-size
6. 静态资源被拦截 → 配置 static-path-pattern
7. JSON 序列化时间戳 → 用 LocalDateTime + jackson
8. 接口未鉴权 → 漏写 .authenticated()
9. Swagger 生产暴露 → @Profile 控制
10. 异常信息暴露给前端 → 用统一 Result 包装

⚠️ 学 Spring Boot 的三大误区
  1. 只学 Spring Boot 不学 Spring：地基不牢，楼会倒。先学 Spring 核心（IoC/AOP/MVC）
  2. 只会用不会看源码：面试一问就懵。Debug 进 Spring 源码看看
  3. 追新不求深：Spring Boot 2.x 主流项目足够，搞懂比追 3.x 新特性重要
💡 给初学者的最后一句话

Spring Boot 的本质是封装：把繁琐的 Spring 配置封装成"开箱即用"。但封装不是黑盒——遇到问题要敢看源码，敢打破封装。

用 → 懂 → 改 → 造，四阶段循环，才能真正掌握。
