Java 从入门到精通 · 系统化学习笔记

01 认识 Java：JVM/JDK/JRE 三件套

Java 的「一次编写，到处执行」到底靠什么

Java 的跨平台能力来自字节码（bytecode）与虚拟机（JVM）。源码 .java 经 javac 编译成字节码 .class，再交给不同平台上的 JVM 解释执行。JVM 把字节码翻译成目标机器指令，所以同一份字节码可以跑在 Windows、Linux、macOS 任何装了 JDK 的机器上。

整个生态分三层，记住下面这张表就不会被面试官绕晕：

组件 全称 作用 面向谁
JVM Java Virtual Machine 运行字节码、内存管理、GC 程序运行的「发动机」
JRE Java Runtime Environment JVM + 核心类库 + 运行时 只运行 Java 程序的「使用者」
JDK Java Development Kit JRE + 编译器 + 调试器 + javadoc 写代码的「开发者」
📖 一句话总结

JDK ⊇ JRE ⊇ JVM。开发装 JDK，运行装 JRE，JVM 是被包含在两者里的核心。

Java 的三大版本体系

刚入门最容易被「Java SE / EE / ME」三个缩写劝退，其实现在只有 Java SE 是真正的主力，其他两个已经合并或退出历史：

版本 全称 现状 学什么
Java SE Standard Edition 主力，持续更新（最新 21 LTS） 语法、集合、并发、JVM
Java EE Enterprise Edition 2017 移交 Eclipse 基金会改名 Jakarta EE Servlet、JPA、Jakarta 系列
Java ME Micro Edition 已基本被 Android 取代 入门阶段不用管
⚠️ 避坑提示

「Java SE」和「Java」在日常语境里基本等价。学 Java 就是学 Java SE。别再被 Java EE 吓到，那是过去给企业服务用的，现在主流是 Spring 全家桶。

Java 的设计语言与典型特征

  • 面向对象：一切皆对象（除了 8 种基本类型）
  • 强类型：变量必须先声明类型，编译器会做严格检查
  • 自动内存管理：GC 帮你回收垃圾，代价是停顿（Stop-The-World）
  • 多线程原生支持：从语言层面提供 synchronized 与 volatile
  • 丰富的生态：Maven Central 上有 50 万 + 第三方库
🧠 速记口诀

「三件套，JDK 装；字节码，跨平台；面向对象 + 强类型；JVM GC 收内存」——面试被问「Java 是什么」，套这套话术 30 秒讲清楚。

02 环境搭建与第一个程序

JDK 下载与版本选择

截至 2026 年，建议直接装 Java 17 LTS（2021 发布，长期支持到 2029）。Java 8 仍极流行，但 17 是当下新项目的默认起点。Java 21 LTS（2023 发布）有虚拟线程等革命特性，想跟最新就选 21。

  • Oracle JDK：商业用要付费，个人/开发免费
  • OpenJDK（推荐）：开源免费，性能完全等价，Adoptium / Eclipse Temurin 是主流发行版
  • GraalVM：Oracle 的高性能 JDK，支持 AOT 原生镜像，新派项目在用

Windows 安装 JDK 17（推荐）

# 1) 从 https://adoptium.net/ 下载 jdk-17.x.x-windows-x64.msi
# 2) 双击安装，记下安装路径，默认：
C:\Program Files\Eclipse Adoptium\jdk-17.0.11.9-hotspot

# 3) 配置环境变量（系统属性 → 高级 → 环境变量）
JAVA_HOME = C:\Program Files\Eclipse Adoptium\jdk-17.0.11.9-hotspot
PATH 末尾追加：%JAVA_HOME%\bin

# 4) 验证（重新打开 cmd）
java -version
javac -version

macOS / Linux 一行命令装 OpenJDK

# macOS (Homebrew)
brew install openjdk@17
sudo ln -sfn /opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk-17.jdk

# Ubuntu / Debian
sudo apt update && sudo apt install openjdk-17-jdk

# 验证
java -version    # 看到 openjdk version "17.x.x" 就 OK
⚠️ 避坑提示

Windows 安装后 一定记得配 JAVA_HOME，否则 Maven、Gradle、IDEA 都找不到 JDK。配完环境变量要重新打开终端才生效（PowerShell 还需要重启 IDE）。

第一个 Hello World：三步跑通

  1. 新建文件 Hello.java（文件名必须与 public class 名一致）
  2. 输入下面代码
  3. 命令行 javac Hello.java → java Hello 
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}

运行：

$ javac Hello.java      # 编译生成 Hello.class（字节码）
$ java Hello            # JVM 解释执行
Hello, Java!

「装 JDK 17，配 JAVA_HOME；javac 编，java 跑；文件名与 public class 同名」——这三句记住，入门第一步稳了。

03 基础语法：变量、类型与运算符

8 种基本数据类型（必须背下来）

Java 是强类型语言，所有变量必须先声明类型再使用。8 种基本类型是 Java 的「基石」，包装类与泛型都围绕它们展开。

类型 关键字 字节数 取值范围 默认值 场景
整型 byte 1 -128 ~ 127 0 底层字节流
整型 short 2 -2^15 ~ 2^15-1 0 极少用
整型 int 4 约 ±21 亿 0 99% 整数场景
整型 long 8 约 ±9.22×10^18 0L 时间戳、大数据 ID
浮点 float 4 约 7 位有效数字 0.0f 几乎不用
浮点 double 8 约 15 位有效数字 0.0d 默认浮点
字符 char 2 0 ~ 65535（UTF-16） '\u0000' 单个字符
布尔 boolean 1 ~ ? true / false false 逻辑判断
⚠️ 避坑提示

boolean 在 JVM 中实际占用 1 字节（int 数组实现），但不能用 0/1 强转，这是 C 语言的遗留思路，Java 里编译器会报错。

变量的声明与作用域

Java 变量分四类：局部变量、成员变量、静态变量、常量。它们的区别直接决定生命周期。 

public class VarScope {
    // 成员变量（实例变量）：每个对象独立，有默认值
    private int age = 18;

    // 静态变量（类变量）：所有对象共享，类加载时初始化
    public static String SCHOOL_NAME = "Java 大学";

    // 常量：必须初始化，不可二次赋值
    public static final double PI = 3.14159;

    public void method(int param) {  // 形参也是「局部变量」
        int local = 10;              // 局部变量：必须手动初始化
        final int FIXED = 100;       // 局部常量
        // local = local + param;    // OK
    }
}

运算符优先级（容易掉的坑）

运算符有优先级，不确定就加括号，别靠肌肉记忆。面试常考：i++ 与 ++i 的区别。 

int a = 5;
int b = a++;   // 先用再加：b = 5，a 变 6
int c = ++a;   // 先加再用：a 变 7，c = 7

// 位运算小技巧
int n = 60;        // 0011 1100
n << 2 = 240;     // 左移 2 位 = 乘 4（注意溢出）
n >> 2  = 15;      // 算术右移 = 除 4（保留符号）
n >>> 2 = 15;      // 逻辑右移（高位补 0）
优先级（高 → 低） 运算符 说明
1（最高） () [] . 括号、数组、点号
2 ! ~ ++ -- 单目
3 * / % 乘除取模
4 + - 加减
5 << >> >>> 位移
6 < <= > >= 关系
7 == != 相等
8 & ^ | 位运算
9 && || 逻辑（推荐代替 8）
10 ?: 三元
11（最低） = += -= … 赋值
🧠 速记口诀

「8 类型，4 整数 2 浮 1 字符 1 布尔；int 是主力，long 加 L；不确定就加括号」——面试被问「int 和 Integer 区别」也用得上（见 ch10 包装类）。

04 流程控制：分支与跳转

if 条件分支

最基础的分支结构。Java 的条件必须是 boolean，不能像 C 那样用整数当真假。 

int score = 85;

if (score >= 90) {
    System.out.println("优秀");
} else if (score >= 75) {
    System.out.println("良好");
} else if (score >= 60) {
    System.out.println("及格");
} else {
    System.out.println("不及格");
}

switch 多路分支（Java 14+ 写法）

Java 14 引入了「switch 表达式」，比传统 switch 更安全简洁，没有「忘记 break 串掉」的问题： 

// Java 8 传统写法（容易漏 break）
String level;
switch (score / 10) {
    case 10:
    case 9: level = "A"; break;
    case 8: level = "B"; break;
    default: level = "C";
}

// Java 14+ switch 表达式（推荐）
String level = switch (score / 10) {
    case 9, 10 -> "A";   // 多值合并
    case 8     -> "B";
    case 7     -> "C";
    default    -> "D";
};

循环三件套：for / while / do-while

// 普通 for：循环次数已知
for (int i = 0; i < 5; i++) {
    System.out.println("第 " + i + " 次");
}

// 增强 for（foreach）：只读遍历
int[] arr = {1, 2, 3, 4, 5};
for (int x : arr) {
    System.out.println(x);
}

// while：条件循环
int n = 0;
while (n < 3) {
    n++;
}

// do-while：至少执行一次
int m = 0;
do {
    m++;
} while (m < 1);   // m = 1，因为先执行后判断
⚠️ 避坑提示

永远不要在循环里修改循环变量（除非你非常清楚后果）。经典翻车：for (int i = 0; i < 10; i++) { i = 0; }——死循环。

break / continue / return：跳出三剑客

关键字 作用 常见场景
break 跳出当前循环 / switch 找到目标提前退出
continue 跳过本轮剩余代码 过滤某些元素
return 跳出整个方法并返回值 函数出口

带标签的 break / continue（跳出多层循环）

outer: for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == 1 && j == 1) {
            break outer;   // 一口气跳出两层
        }
        System.out.println(i + "," + j);
    }
}
🧠 速记口诀

「条件要 boolean，switch 用 → 表达式；break 出当前，continue 跳本轮；带标签能跳外层」——三剑客配 switch 表达式，流程控制毕业。

05 数组、字符串与常用类

一维数组

Java 数组是对象（继承自 Object），有 length 属性，固定大小。需要变长就用 ArrayList（见 ch10）。 

// 三种声明方式
int[] a1 = new int[5];              // 默认值 0
int[] a2 = {1, 2, 3, 4, 5};          // 字面量
int[] a3 = new int[]{1, 2, 3};       // 匿名数组

// Arrays 工具类（java.util.Arrays）
int[] nums = {3, 1, 4, 1, 5, 9, 2, 6};
Arrays.sort(nums);                  // 排序
System.out.println(Arrays.toString(nums)); // [1, 1, 2, 3, 4, 5, 6, 9]
int idx = Arrays.binarySearch(nums, 5);  // 二分查找（要先排序）
int[] copy = Arrays.copyOf(nums, nums.length);

二维数组（锯齿数组）

Java 二维数组其实是「数组的数组」，每行长度可以不同： 

int[][] matrix = {
    {1, 2, 3},
    {4, 5},
    {6, 7, 8, 9}     // 每行长度不同 → 锯齿数组
};
System.out.println(matrix[2][3]);   // 9
System.out.println(matrix.length);  // 3（行数）
System.out.println(matrix[0].length); // 3（第 0 行列数）

String 不可变字符串（最常用的类）

String 是不可变对象（immutable），每次「修改」其实都是新建对象。这是为了安全（HashMap 的 key、URL、数据库连接池）和线程安全。 

String s = "Hello";           // 字面量进字符串常量池
String t = new String("Hello"); // new 出来的在堆上
System.out.println(s == t);     // false（== 比较地址）
System.out.println(s.equals(t)); // true（equals 比较内容）

// 拼接：编译器会自动转 StringBuilder
String r = "a" + "b" + "c";    // 编译后等价于 new StringBuilder().append("a").append("b").append("c").toString();

// 高频 API
"  hello world  ".trim().toUpperCase().substring(2, 7); // "HELLO"
"abc".repeat(3);             // Java 11+："abcabcabc"
"".isEmpty();                // true
"".isBlank();                // Java 11+：true（含 Unicode 空格）
⚠️ 避坑提示

循环里不要用 + 拼字符串，会生成大量中间对象。批量拼接用 StringBuilder，单线程；多线程用 StringBuffer（带 synchronized）。

StringBuilder / StringBuffer

// StringBuilder：非线程安全，性能更高（推荐）
StringBuilder sb = new StringBuilder(64);
for (int i = 0; i < 1000; i++) {
    sb.append(i).append(",");
}
String result = sb.toString();

// StringBuffer：线程安全，所有方法带 synchronized
StringBuffer sbf = new StringBuffer(); // 几乎只在历史代码里见

常用包装类（基本类型 → 对象）

集合和泛型不允许基本类型，必须用包装类。Java 5+ 自动装箱 / 拆箱。

基本类型 包装类 缓存范围
int Integer -128 ~ 127
long Long -128 ~ 127
double Double 无缓存
boolean Boolean 静态 TRUE/FALSE
📖 面试常见坑

Integer i1 = 100; Integer i2 = 100; i1 == i2 → true（命中缓存）。但 Integer j1 = 200; j2 = 200; j1 == j2 → false（缓存外）。所以比较包装类要用 equals。

BigInteger 与 BigDecimal（高精度计算）

// 任意精度整数
BigInteger a = new BigInteger("123456789012345678901234567890");

// 金额：必须用 String 构造，避免 double 精度丢失
BigDecimal price = new BigDecimal("19.99");      // 推荐
BigDecimal wrong = new BigDecimal(19.99);         // 坑！仍是 double 转的
price.multiply(BigDecimal("3")).toString();       // 计算总价
🧠 速记口诀

「数组固定长，String 不可变；批量拼 StringBuilder；金额用 BigDecimal 字符串构造；包装类比较用 equals」——数组、字符串、常用类一网打尽。

06 方法、递归与参数传递

方法定义四要素

[修饰符] 返回值类型 方法名(参数列表) [throws 异常] {
    方法体;
    return 返回值;   // void 可省略
}

// 示例：求两数最大公约数（欧几里得算法）
public static int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);   // 递归
}
修饰符 作用 组合
public 所有包可访问 通常组合：public static final（常量）
protected 同包 + 子类
private 仅本类
static 类级，不依赖对象
final 不可重写 / 继承
abstract 抽象方法

方法重载（Overload）：同名不同参

同一类中，方法名相同但参数列表不同（个数 / 类型 / 顺序），编译时静态绑定。返回类型不同不算重载。 

public class MathUtils {
    public int add(int a, int b)         { return a + b; }
    public double add(double a, double b) { return a + b; }  // 参数类型不同
    public int add(int a, int b, int c)  { return a + b + c; } // 参数个数不同
}

方法重写（Override）：父子不同实现

子类完全相同签名的方法覆盖父类，运行时动态绑定（多态的基础）。 

class Animal {
    public void speak() { System.out.println("动物叫"); }
}
class Dog extends Animal {
    @Override                    // 编译器帮你检查签名
    public void speak() { System.out.println("汪汪"); }
}

Animal a = new Dog();
a.speak();                      // 输出「汪汪」——多态

Java 的「值传递」永远成立

Java 严格说只有值传递。对基本类型传值的拷贝；对对象传「对象引用的拷贝」（即指针的拷贝）。 

public static void swap(int a, int b) {  // a, b 是原值的拷贝
    int t = a; a = b; b = t;        // 只换了副本
}
// 调用后原变量不变

public static void reset(User u) {   // u 是引用的副本
    u = new User();                  // 只让副本指向新对象
}
// 调用方持有的引用仍然指向原对象

// 想真的「清空」，必须操作对象自身
public static void clear(User u) {
    u.setName(null);                 // 改的是同一个对象
}
⚠️ 避坑提示

面试经典题：「Java 是值传递还是引用传递？」答案：严格值传递。对象传的是「引用的值」。所以方法里改引用指向不能让外面变，但改对象内部字段可以。

递归：自己调自己

递归三要素：终止条件、递推关系、返回时机。经典案例：阶乘、斐波那契、二分查找、快排。 

// 阶乘 n! = n * (n-1)!
public static long factorial(int n) {
    if (n <= 1) return 1;     // 终止条件
    return n * factorial(n - 1);
}

// 斐波那契（朴素递归 O(2^n) 极慢）
public static long fib(int n) {
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
// 推荐：迭代版 O(n)
public static long fibIter(int n) {
    if (n < 2) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        long t = a + b; a = b; b = t;
    }
    return b;
}
🧠 速记口诀

「方法四要素：修饰返回名参数；重载看参数，重写看父子；Java 永远值传递；递归三件套：终止递推返回」——这一章面试命中率最高的就是重载、重写、值传递三连问。

07 面向对象三大特性

封装：藏起来，露接口

把数据（字段）和操作（方法）封装在类里，对外只暴露必要的 getter / setter。好处：可维护、可校验、可变更内部实现而不影响调用方。 

public class Account {
    private double balance;            // 字段私有

    public double getBalance() {       // 只读 getter
        return balance;
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("金额必须 > 0");
        balance += amount;
    }
}

继承：复用代码、表达 is-a

Java 类单继承（一个父类），接口多继承。子类继承父类的非 private 字段与方法，可重写。 

class Animal {
    protected String name;
    public void eat() { System.out.println(name + " 吃东西"); }
}
class Dog extends Animal {
    public Dog(String name) { this.name = name; }
    public void bark() { System.out.println("汪汪"); }
}
关键字 作用 典型场景
extends 声明父类 class Dog extends Animal
super 访问父类成员 super(name) 调父构造
this 访问当前对象 this.name = name
final 禁止继承 / 重写 public final class String

多态：父类引用指向子类对象

多态的三要素：继承、重写、父类引用指向子类对象。运行时根据对象的实际类型调用对应方法（动态分派）。 

Animal a = new Dog("旺财");
a.eat();    // 编译时看 Animal，运行时调 Dog（如果 Dog 重写了）

// 实际意义：写一个方法处理所有 Animal 子类
public void feed(Animal animal) {     // 接受父类类型
    animal.eat();                     // 自动调用对应子类实现
}

构造方法与初始化顺序

对象初始化顺序面试必考：父静态 → 子静态 → 父实例块/字段 → 父构造 → 子实例块/字段 → 子构造。 

class Parent {
    static { System.out.println("父类 static"); }
    { System.out.println("父类 实例块"); }
    Parent() { System.out.println("父类 构造"); }
}
class Child extends Parent {
    static { System.out.println("子类 static"); }
    { System.out.println("子类 实例块"); }
    Child() { System.out.println("子类 构造"); }
}
// new Child() 输出顺序：
// 父类 static → 子类 static → 父类 实例块 → 父类 构造 → 子类 实例块 → 子类 构造
⚠️ 避坑提示

每个类都有构造方法。没写就编译器自动加无参构造；一旦写了带参构造，无参构造就不再自动生成——子类继承时容易踩这个坑。

访问修饰符的可见范围

修饰符 同类 同包 子类 其他包
public ✓ ✓ ✓ ✓
protected ✓ ✓ ✓ ✗
无（默认） ✓ ✓ ✗ ✗
private ✓ ✗ ✗ ✗
🧠 速记口诀

「封装藏实现、继承 is-a、多态父引子；初始化顺序：父静 → 子静 → 父实 → 父构 → 子实 → 子构」——三大特性 + 初始化顺序，OOP 核心全部拿下。

08 抽象类、内部类与接口

抽象类（abstract class）

用 abstract 修饰的类，不能 new，可以包含抽象方法（只有声明没有实现）。常用于「模板方法模式」。 

abstract class Shape {
    String color;

    // 抽象方法：子类必须实现
    abstract double area();

    // 具体方法：子类继承即可
    public String describe() {
        return color + "的图形，面积 = " + area();
    }
}
class Circle extends Shape {
    double r;
    public Circle(double r) { this.r = r; color = "红色"; }
    @Override
    double area() { return Math.PI * r * r; }
}

接口（interface）：纯契约

Java 8+ 接口可以有 default 方法和 static 方法。一个类可以实现多个接口，是多继承的救赎。 

interface Flyable {
    void fly();
    default void land() { System.out.println("降落"); }   // Java 8+ 默认实现
    static void check() { System.out.println("飞行前检查"); }
}
interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {   // 多实现
    @Override public void fly() { System.out.println("鸭子飞"); }
    @Override public void swim() { System.out.println("鸭子游"); }
}

抽象类 vs 接口对比

维度 抽象类 接口
关键字 abstract class interface
继承数量 单继承 多实现
字段 任意 默认 public static final
方法 任意 默认 public abstract（Java 8+ 可有 default/static）
构造方法 有 无
使用场景 「is-a」 + 共性代码 「has-a」能力扩展

四种内部类

class Outer {
    private int x = 10;

    // 1. 成员内部类：依赖外部类对象
    class Inner {
        public void show() { System.out.println(x); }
    }

    // 2. 静态内部类：不依赖外部类对象
    static class StaticInner {
        public void show() { System.out.println("static"); }
    }

    // 3. 局部内部类：定义在方法里
    public void method() {
        class LocalInner { }
    }

    // 4. 匿名内部类：一次性使用
    Runnable r = new Runnable() {
        @Override public void run() { System.out.println("匿名"); }
    };
}
⚠️ 避坑提示

匿名内部类会捕获外部 final 变量（Java 8+ 等价 final 也行）。Lambda 表达式（Java 8+）能取代大部分匿名内部类场景。

🧠 速记口诀

「抽象类是模板，接口是契约；接口多实现，类单继承；内部类四种：成员/静态/局部/匿名」——抽象类与接口是面试 OOP 高频考点。

09 异常处理机制

异常的层次结构

Java 把所有异常用类层次组织，全部继承自 Throwable： 

java.lang.Throwable
 ├── Error           （系统级，无法恢复，不应捕获）
 │    ├── OutOfMemoryError
 │    └── StackOverflowError
 └── Exception        （程序级，应该处理）
      ├── RuntimeException（运行时异常，编译器不强制捕获）
      │    ├── NullPointerException
      │    ├── ArrayIndexOutOfBoundsException
      │    ├── ClassCastException
      │    └── ArithmeticException
      └── 受检异常（checked，必须捕获或声明 throws）
           ├── IOException
           ├── SQLException
           └── ParseException
类别 是否受检 是否必须捕获 举例
Error 否 不应该捕获 OOM、StackOverflow
RuntimeException 否（非受检） 建议处理，但不强制 NPE、数组越界
其他 Exception 是（受检） 必须 try-catch 或 throws IO、SQL 异常

try-catch-finally：标准处理结构

try {
    // 可能抛异常的代码
    int n = Integer.parseInt("abc");
} catch (NumberFormatException e) {        // 精准捕获
    System.out.println("数字格式不对");
    e.printStackTrace();                   // 打堆栈
} catch (Exception e) {                    // 多 catch，先子类后父类
    System.out.println("其他异常");
} finally {
    System.out.println("无论如何都执行");   // 适合释放资源
}

try-with-resources（Java 7+ 推荐写法）

凡是实现 AutoCloseable 的类（流、连接等）都能自动关闭，比 finally 干净： 

// 老写法：finally 里手动关
FileInputStream in = null;
try {
    in = new FileInputStream("a.txt");
    // ...
} finally {
    if (in != null) in.close();
}

// 新写法（推荐）：自动关闭
try (FileInputStream in = new FileInputStream("a.txt");
     BufferedReader br = new BufferedReader(new InputStreamReader(in))) {
    String line = br.readLine();
}   // 离开 try 块自动调 close()，即使抛异常也关

throw 与 throws 的区别

关键字 位置 作用
throw 方法体内 手动抛出一个异常对象
throws 方法签名后 声明可能抛的异常，把责任推给调用方 
// 自定义业务异常
public class BizException extends RuntimeException {
    public BizException(String msg) { super(msg); }
}

// throws 声明
public void read(String fileName) throws IOException {     // 告诉调用方可能 IO 异常
    if (!new File(fileName).exists()) {
        throw new FileNotFoundException(fileName);          // 手动抛
    }
}

自定义异常与最佳实践

  • 异常类名以 Exception 结尾
  • 提供「带 message」的构造方法
  • 业务异常继承 RuntimeException，避免污染方法签名
  • 不要用异常做流程控制（性能差、语义不清）
🧠 速记口诀

「Throwable 下 Error + Exception；运行时非受检，IO/SQL 受检；try-with-resources 自动关；throw 抛，throws 声明」——异常处理核心四件套。

10 集合框架：List / Set / Map

集合整体结构

Java 集合分两大族：Collection（存单值）和 Map（存键值对）。Collection 下又分 List（有序可重复）、Set（无序不可重复）、Queue（队列）。 

Iterable
 └── Collection
      ├── List（有序可重复）
      │    ├── ArrayList    数组实现，随机访问快，增删慢
      │    ├── LinkedList   链表实现，增删快，随机访问慢
      │    └── Vector       古老线程安全版本（几乎不用）
      ├── Set（去重）
      │    ├── HashSet       基于 HashMap，O(1) 增删查
      │    ├── LinkedHashSet 保留插入顺序
      │    └── TreeSet        基于红黑树，元素有序
      └── Queue
           ├── ArrayDeque    双端队列
           └── PriorityQueue 优先队列（堆）
Map（键值对，键唯一）
 ├── HashMap       O(1) 增删查（最常用）
 ├── LinkedHashMap 保留插入顺序
 ├── TreeMap        Key 有序
 └── ConcurrentHashMap  并发场景

List 三巨头对比

维度 ArrayList LinkedList Vector
底层 动态数组 双向链表 动态数组
随机访问 O(1) ★ O(n) O(1)
头尾增删 O(n)（需要扩容） O(1) ★ O(n)
线程安全 否 否 是（synchronized）
默认容量 10 — 10
扩容 1.5 倍 — 2 倍
建议 默认用它 队列场景 历史代码

ArrayList 与 LinkedList 选择

// 99% 场景用 ArrayList
List<String> list = new ArrayList<>(64);   // 预设容量避免多次扩容
list.add("a");
list.get(0);                                  // O(1) 随机访问
list.set(0, "A");                             // 修改

// 真要频繁头插 / 队列 / 栈 → LinkedList
Deque<Integer> queue = new LinkedList<>();
queue.offer(1);     // 入队
queue.poll();        // 出队
queue.peek();        // 看队首

Set 去重原理：HashSet 背后的 HashMap

Set<String> set = new HashSet<>();
set.add("a");     // 实际是 HashMap.put("a", PRESENT)，PRESENT 是固定占位对象
set.contains("a");  // O(1) 哈希定位

// 必须正确实现 hashCode 与 equals，否则会去重失败
class User {
    String name;
    int age;
    @Override public boolean equals(Object o) { /* 比较 name + age */ }
    @Override public int hashCode() { return Objects.hash(name, age); }
}
⚠️ 避坑提示

放进 HashSet/HashMap 的对象必须同时重写 equals 和 hashCode，否则去重失效、查找错乱。可以用 Objects.equals 和 Objects.hash 避免空指针。

Map 重点：HashMap 实现原理

Java 8+ 的 HashMap = 数组 + 链表 + 红黑树。当链表长度 > 8 且数组 ≥ 64 时，链表转红黑树，查找从 O(n) 变成 O(log n)。 

Map<String, Integer> map = new HashMap<>(64, 0.75f);
// initialCapacity = 64（数组大小），loadFactor = 0.75（扩容阈值）

map.put("a", 1);
map.getOrDefault("b", 0);     // key 不存在返回 0
map.computeIfAbsent("c", k -> 0);  // key 不存在才计算

// 遍历
for (Map.Entry<String, Integer> e : map.entrySet()) {
    System.out.println(e.getKey() + "=" + e.getValue());
}

如何选择集合？一张表搞定

需求 选
快速随机访问、可重复 ArrayList
频繁头尾增删 LinkedList 或 ArrayDeque
去重 + 顺序无关 HashSet
去重 + 保留插入顺序 LinkedHashSet
去重 + 元素有序 TreeSet
键值对 + 顺序无关 HashMap
键值对 + 保留插入顺序 LinkedHashMap
键值对 + key 排序 TreeMap
并发场景 ConcurrentHashMap / CopyOnWriteArrayList
🧠 速记口诀

「List 有序可重，Set 去重，Map 键值；查询 ArrayList，去重 HashSet，键值 HashMap；Java 8 起 HashMap 链表长 8 转红黑树」——面试三连问标准答案。

11 泛型与通配符

为什么需要泛型

泛型让类 / 接口 / 方法支持多种类型，同时在编译期做类型检查，避免运行时才 ClassCastException。 

// 不带泛型：每次取出都要强转
List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0);   // 必须强转，容易 ClassCastException

// 带泛型：编译期就保证类型
List<String> list2 = new ArrayList<>();
list2.add("hello");
String s2 = list2.get(0);          // 直接是 String，不用转

泛型类 / 接口 / 方法

// 泛型类
public class Box<T> {
    private T value;
    public void set(T v) { this.value = v; }
    public T get() { return value; }
}
Box<String> box = new Box<>();     // Java 7+ 菱形语法

// 泛型方法：<T> 声明独立于类的泛型
public static <T> T identity(T input) {
    return input;
}
String r = identity("abc");        // T 推断为 String

// 多类型参数
public class Pair<K, V> {
    public Pair(K k, V v) { }
}

通配符：? extends / ? super

PECS 原则（Producer Extends, Consumer Super）是泛型面试必考题：

// 上界通配：只能读，不能写（生产者）
public double sumOfList(List<? extends Number> list) {
    double sum = 0;
    for (Number n : list) sum += n.doubleValue();   // OK：能读 Number
    // list.add(1.0);   // 编译错！不知道具体子类型
    return sum;
}

// 下界通配：只能写，不能读（消费者）
public void addNumbers(List<? super Integer> list) {
    list.add(1);                  // OK：能写 Integer（必被接受）
    // Integer i = list.get(0);   // 编译错！只知是 Integer 的父类
}
通配符 读 写 场景
<? extends T> 可读为 T 不可写 生产者（从集合「取」数据）
<? super T> 读出来是 Object 可写 T 消费者（往集合「放」数据）
<?> 读为 Object 只能写 null 完全不确定
⚠️ 避坑提示

泛型是编译期特性，运行期会擦除（erasure）成 Object 或上界。所以 List<String> 和 List<Integer> 运行时其实是同一个类，不能用 instanceof 检查泛型类型。

类型擦除的影响

// 编译后等价于：
// class Box { private Object value; ... }

List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());   // true，同一个 ArrayList.class

// 不能 new T()、不能 new T[]、不能 instanceof T
// 解决：Class<T> clazz 参数传入，或用反射
🧠 速记口诀

「泛型三类：类接口方法；通配符 PECS：extends 读 super 写；运行期类型擦除变 Object」——泛型面试题就这三板斧。

IO 流的整体分类

按方向分：输入流（Input）/ 输出流（Output）。按数据类型分：字节流（byte）/ 字符流（char）。下面这张表记牢：

文件 FileInputStream FileOutputStream FileReader FileWriter

转换 — InputStreamReader OutputStreamWriter

经典字节流读写文件

// 复制文件（推荐写法：try-with-resources + 缓冲流）
Path src = Path.of("a.txt");
Path dst = Path.of("b.txt");
try (InputStream in = new BufferedInputStream(Files.newInputStream(src));
     OutputStream out = new BufferedOutputStream(Files.newOutputStream(dst))) {
    byte[] buf = new byte[8192];
    int n;
    while ((n = in.read(buf)) != -1) {
        out.write(buf, 0, n);
    }
}

字符流读文本（按行）

// Java 11+ Files.readString 一行搞定
String content = Files.readString(Path.of("config.json"));

// 按行读
try (BufferedReader br = Files.newBufferedReader(Path.of("data.csv"))) {
    String line;

        String[] cols = line.split(",");
    }

对象序列化（Serializable）

public class User implements Serializable {  // 打标记
    private static final long serialVersionUID = 1L;  // 版本号
    private String name;
    private transient String password;        // 不参与序列化
}

// 序列化
User u = new User("张三", "123");
try (ObjectOutputStream oos = new ObjectOutputStream(
        new FileOutputStream("user.bin"))) {
    oos.writeObject(u);
}

// 反序列化
try (ObjectInputStream ois = new ObjectInputStream(
        new FileInputStream("user.bin"))) {
    User u2 = (User) ois.readObject();

}
⚠️ 避坑提示

Serializable 反序列化有安全风险（反序列化攻击），且对类结构变更敏感。生产项目更推荐用 JSON（Jackson / Gson），而不是 Java 原生序列化。

NIO.2（Java 7+）：Files / Paths / Path

新 IO API 用 Path 替代 File，支持异步（AsynchronousChannel）和文件属性操作。 

Path p = Path.of("/tmp", "a.txt");

Files.exists(p);
Files.size(p);
Files.deleteIfExists(p);
Files.list(Path.of("/tmp"))          // 流式遍历目录
    .filter(Files::isRegularFile)
    .forEach(System.out::println);

// 递归遍历：Files.walk 返回 Stream<Path>
try (Stream<Path> stream = Files.walk(Path.of("/tmp"))) {
    long count = stream.filter(Files::isRegularFile).count();
}
🧠 速记口诀

「字节流图片视频，字符流文本；缓冲流包一层，性能翻倍；序列化加 Serializable、慎用；新 IO 用 Path + Files」——IO 学习一句话回顾。

13 多线程与 JUC 并发包

线程的两种创建方式

// 方式 1：继承 Thread 类
class MyThread extends Thread {
    @Override public void run() {
        System.out.println("线程运行");
    }
}
new MyThread().start();

// 方式 2（推荐）：实现 Runnable / Callable
Runnable task = () -> System.out.println("Lambda 写法");

// Callable：可返回结果，可抛异常
Callable<Integer> callTask = () -> {
    Thread.sleep(1000);
    return 42;
};
ExecutorService pool = Executors.newFixedThreadPool(4);
Future<Integer> future = pool.submit(callTask);
Integer result = future.get();            // 阻塞等结果
pool.shutdown();

线程生命周期（6 种状态）

NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED
 ↑
 new Thread()  start()         阻塞 / 等待        run() 结束

NEW         新建未启动
RUNNABLE    正在 JVM 中执行（含就绪）
BLOCKED     等待进入 synchronized
WAITING     Object.wait() / join() 无限等
TIMED_WAITING sleep() / wait(timeout)
TERMINATED  执行完毕

synchronized 与 volatile

// 1. 修饰实例方法：锁 this
public synchronized void increment() { count++; }

// 2. 修饰静态方法：锁 Class 对象
public static synchronized void doWork() { }

// 3. 修饰代码块：锁指定对象
synchronized (lock) {
    // 临界区
}

// volatile：保证可见性 + 禁止指令重排，不保证原子性
private volatile boolean flag = false;
⚠️ 避坑提示

volatile 不能替代 synchronized。它只保证线程间可见，不保证 i++ 这种复合操作的原子性。需要原子操作用 AtomicInteger。

JUC 核心组件

组件 作用 典型场景
AtomicInteger/Long 无锁原子类（CAS） 计数器、状态标记
ReentrantLock 可重入锁 需要 tryLock / 公平锁
CountDownLatch 倒计数到 0 放行 主线程等子线程结束
CyclicBarrier 循环屏障 多线程分阶段汇总
Semaphore 信号量限流 池化资源（数据库连接）
ConcurrentHashMap 并发 Map 并发缓存
ThreadPoolExecutor 线程池 99% 场景用它

线程池七大参数

new ThreadPoolExecutor(
    2,                          // corePoolSize 核心线程数
    8,                          // maximumPoolSize 最大线程数
    60, TimeUnit.SECONDS,       // keepAliveTime 非核心空闲存活时间
    new LinkedBlockingQueue<>(100),  // workQueue 任务队列
    Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
);

四种拒绝策略：

策略 行为
AbortPolicy 抛异常（默认）
CallerRunsPolicy 让提交者自己跑
DiscardPolicy 静默丢弃
DiscardOldestPolicy 丢最老的任务
⚠️ 避坑提示

禁用 Executors.newFixedThreadPool 默认队列容量 Integer.MAX_VALUE，可能 OOM。生产环境必须显式构造 ThreadPoolExecutor，指定队列容量。

Java 21 虚拟线程（Virtual Threads）

Java 21 引入了「虚拟线程」，也称协程。百万级线程轻松搞定，适合高并发 I/O 场景（Web 服务器、HTTP 客户端）。 

// Java 21+
Thread.ofVirtual().start(() -> {
    System.out.println("虚拟线程");
});

// 虚拟线程池
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 100_000; i++) {
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));
            return null;
        });
    }
}   // 自动 join
🧠 速记口诀

14 JVM 内存模型与 GC 调优

JVM 运行时数据区

面试必问：堆 / 栈 / 方法区 / PC 寄存器 / 本地方法栈。重点记线程私有 vs 共享。

区域 线程私有 作用 OOM 现象
堆 Heap 否 对象实例、数组 OutOfMemoryError: Java heap space
虚拟机栈 Stack 是 方法栈帧、局部变量 StackOverflowError
程序计数器 PC 是 当前线程字节码行号 不会 OOM
本地方法栈 是 Native 方法 StackOverflowError
方法区 / 元空间 否 类信息、常量池、静态变量 OutOfMemoryError: Metaspace

堆内存分代模型

                    ┌─────────────┐
                    │    老年代    │  长期存活对象
                    │   Old Gen   │  Full GC 触发
                    └─────────────┘
                          ▲
                          │ 晋升（年龄阈值 15）
                    ┌─────────────┐
                    │   幸存区    │  From / To
                    │   Survivor  │  Minor GC 反复复制
                    └─────────────┘
                          ▲
                    ┌─────────────┐
                    │   新生代    │  Eden + 2 Survivor
                    │   Young Gen │  Minor GC 频繁
                    └─────────────┘

Java 8+ 默认：-Xms4g -Xmx4g -Xmn2g （新生代 2G）
HotSpot 默认比例：Eden : Survivor : Survivor = 8 : 1 : 1

垃圾回收算法（4 种）

算法 原理 优缺点
标记-清除 先标记后清 有内存碎片
标记-整理 清除后整理 无碎片，但慢
复制 分两块，活对象复制到另一边 无碎片，但要双倍空间（用于新生代）
分代 按对象年龄分代回收 现代 JVM 默认算法

常用垃圾回收器

回收器 算法 特点 JDK 默认
Serial 复制 + 标记整理 单线程，STW —
Parallel Scavenge 多线程复制 吞吐量优先 Java 8 默认
G1 分区 + 增量 低延迟 + 大堆 Java 9+ 默认
ZGC 染色指针 + 读屏障 亚毫秒级 STW，TB 级堆 Java 11+ 实验
Shenandoah Brooks 指针 类似 ZGC，RedHat 主推 Java 12+ 实验

15 反射、注解与动态代理

反射：在运行时看 & 改类的一切

反射让 Java 突破「编译期静态」，运行时动态拿类的字段、方法、构造器。框架（Spring/MyBatis）的基石。 

// 三步：拿 Class → 拿 Constructor/Method/Field → 调用
Class<?> clazz = Class.forName("com.example.User");
Object user = clazz.getDeclaredConstructor(String.class, int.class)
                 .newInstance("张三", 18);

Method setName = clazz.getDeclaredMethod("setName", String.class);
setName.invoke(user, "李四");           // 调用 setter

Field nameField = clazz.getDeclaredField("name");
nameField.setAccessible(true);           // 关 private 权限校验
System.out.println(nameField.get(user)); // 拿到 "李四"
⚠️ 避坑提示

setAccessible(true) 能绕过 private 访问，生产代码慎用。反射比直接调用慢 10~100 倍，JIT 优化难。高频调用应避免反射，或用 MethodHandle（Java 7+）替代。

注解：元数据 + 处理

注解本质是「给代码贴标签」，本身不改变程序行为，要配合反射或 APT才生效。 

// 1. 定义注解
@Retention(RetentionPolicy.RUNTIME)     // 保留到运行期
@Target(ElementType.METHOD)             // 只能贴在方法上
public @interface Cacheable {
    String key();
    int expire() default 60;
}

// 2. 使用注解
class UserService {
    @Cacheable(key = "user:", expire = 300)
    public User findById(Long id) { return null; }
}

// 3. 解析注解（Spring AOP 的核心思路）
Method m = UserService.class.getMethod("findById", Long.class);
if (m.isAnnotationPresent(Cacheable.class)) {
    Cacheable c = m.getAnnotation(Cacheable.class);
    System.out.println(c.key());          // "user:"
}
保留策略 生效阶段 典型场景
SOURCE 源码期 @Override（编译器用）
CLASS 字节码期 APT 编译期生成代码
RUNTIME 运行期 Spring 框架用

JDK 动态代理（基于接口）

// 业务接口
interface Service {
    void doWork();
}

// 被代理对象
class RealService implements Service {
    public void doWork() { System.out.println("真实工作"); }
}

// 调用处理器：每个方法调用都会经过这里
InvocationHandler handler = (proxy, method, args) -> {
    System.out.println("[日志] 调用 " + method.getName());
    Object result = method.invoke(new RealService(), args);
    System.out.println("[日志] 结束");
    return result;
};

Service proxy = (Service) Proxy.newProxyInstance(
    Service.class.getClassLoader(),
    new Class<?>[]{Service.class},
    handler);
proxy.doWork();   // 自动加日志

CGLIB / ByteBuddy 动态代理（基于类）

JDK 代理要求有接口，没有接口就用 CGLIB（生成子类）或 ByteBuddy（字节码增强）。Spring AOP 默认两者混用。

🧠 速记口诀

「反射拿类三步走；注解三保留期；JDK 代理要接口，CGLIB 生成子类；Spring 框架都是这两套」——理解框架的「钥匙三件套」。

单例模式：六种写法对比

// 1. 饿汉式（类加载即创建，线程安全）
public class Singleton1 {
    private static final Singleton1 INSTANCE = new Singleton1();
    private Singleton1() {}
    public static Singleton1 getInstance() { return INSTANCE; }
}

// 2. 懒汉式 + 双重检查锁（DCL，推荐面试写）
public class Singleton2 {
    private static volatile Singleton2 INSTANCE;   // volatile 防指令重排
    private Singleton2() {}
    public static Singleton2 getInstance() {
        if (INSTANCE == null) {                      // 第一次检查（无锁）
            synchronized (Singleton2.class) {
                if (INSTANCE == null) {              // 第二次检查（加锁后）
                    INSTANCE = new Singleton2();
                }
            }
        }
        return INSTANCE;
    }
}

// 3. 静态内部类（最优雅）
public class Singleton3 {
    private Singleton3() {}
    private static class Holder {
        private static final Singleton3 INSTANCE = new Singleton3();
    }
    public static Singleton3 getInstance() { return Holder.INSTANCE; }
}

策略模式：消除 if-else

// 业务：根据 type 选择不同算法
interface DiscountStrategy { double apply(double price); }

class FullReduction implements DiscountStrategy {
    public double apply(double p) { return p * 0.7; }
}
class NoDiscount implements DiscountStrategy {
    public double apply(double p) { return p; }
}

Map<String, DiscountStrategy> map = Map.of(
    "FULL", new FullReduction(),
    "NONE", new NoDiscount()
);
double finalPrice = map.get(type).apply(originalPrice);

原则 核心 反例

LSP 里氏替换 子类可替代父类 子类重写搞特殊
